Setup panel

The admin dashboard lists, on its right, each outside service that still needs connecting, says why it matters, and links to the settings page that connects it. It lists only what is still to do, and goes away once everything is done.

What it is

A panel titled Finish setting up, with the number of rows left, on /admin/dashboard. Each row has the service's name, a Needed or Optional tag, one line on why to set it up, and a button to its settings page: Set up for something not connected yet, Check (on an amber row) for something connected but not working for real yet, such as a test provider.

Needed rows come first, then optional ones, each group in the order above, then the app's own rows.

While the Google Analytics row asks to connect, the dashboard's analytics section is one line saying it is not connected, with no button of its own, so the panel is the one place to set it up. While the row is the amber nobody-tracked warning, the dashboard leaves out its own line saying the same above the numbers. An admin who cannot see the panel's row gets the full card with Set up analytics, as before. Geolocation is not a row: it is off unless you turn it on, and works without a key.

Turn it on or off

The panel is core, always there for admins (the dashboard is admin-only). A row whose feature is off in src/custom/features.ts is never checked or shown (see Choose your app's features). There is no switch for the panel itself, and no button to hide a row: it lists strictly what is pending.

Set it up

Nothing to set up for the panel itself. Open the admin dashboard, and for each row click Set up or Check: it opens that service's settings page, which explains the rest. Come back to the dashboard and the row is gone once the service is connected.

Use it

  • The panel reads the settings each time the dashboard opens. Connect a service, come back to the dashboard, and its row is gone.
  • While the checks run, nothing is shown, so a site that is set up never sees the panel flash.
  • On a wide screen it is a column on the right. Below 992 pixels it sits above the dashboard cards, full width.
  • The − button beside the heading folds the panel into a small Finish setting up button with the number of rows left, at the top right of the dashboard, and the cards take the full width. The button is red while a needed row is left, amber when only optional ones are. Click it to open the panel again. The choice is remembered in that browser only (local storage key arc_setup_panel_collapsed), and the number keeps up with what is still to do.
  • A check that cannot read its settings (offline, or a permission error) leaves its row out rather than raising a false alarm, and logs the error in the browser console.
  • The checks only ask whether a key is saved. No key's value is shown or sent anywhere.

The panel replaced the dashboard's "Email not configured" and "Debug Provider active" banners. The Forms page keeps its own email banner, because there it explains why that page's email controls are off (see Banners).

Extend it

Add the app's own items

An app that needs an admin to connect a service of its own adds a row in src/custom/setup-items.ts, which Arc CMS ships empty:

import type { SetupItem } from '../app/core/setup/setup-items';

export const CUSTOM_SETUP_ITEMS: SetupItem[] = [
    {
        id: 'maps',
        icon: 'fa-solid fa-map',
        route: '/admin/maps-settings',
        pending: async (read) => {
            const maps = await read('maps');           // the Settings/maps document
            return maps?.['apiKey'] ? null : {
                required: false,
                title: 'Maps',
                titleKey: 'app.setup.maps_title',       // optional, from src/custom/i18n
                why: 'Show each shop on a map.',
                whyKey: 'app.setup.maps_why',
            };
        },
    },
];
FieldWhat it is
idUnique among Arc CMS's rows (email, sms, payments, ai, unsplash) and the app's. A repeated id is left out, with a console error.
featureOptional: a feature id; the row is left out while that feature is off.
icon, routeA Font Awesome class, and where the button goes.
pending(read)Returns null when nothing is to do, or what is. read(id) gives the Settings/<id> document, read once for all rows; a check may read anything else it needs. A check that throws is left out.

What pending returns: required (Needed or Optional), title and why as written, with optional titleKey and whyKey translation keys (the written text shows when a key has no translation), warning: true for an amber row with a Check button, and route when this need's button should open another page than the item's own route.

Arc CMS's own rows

Arc CMS's own rows are in src/app/core/setup/setup-items.ts, one rule per service, and SetupStatusService in src/app/core/setup/setup-status.service.ts runs them. A new outside service in core gets its row there, with a test in setup-items.spec.ts.

What it stores

Nothing on the server. Whether the panel is folded is kept in the browser (local storage key arc_setup_panel_collapsed). The panel reads the Settings documents the settings pages already write: email_status, sms, users (whether phone sign-in is on), dodo-payments, ai and integrations, each once when the dashboard opens, plus whatever an app's own rows read.

Troubleshooting

ProblemFix
A service is connected but its row is still thereRead the row's line: an amber row means connected but not live yet (a test provider, test mode, or a key that failed since it last worked). Switch to the real provider or live mode, or test the key on its settings page, then reopen the dashboard.
A row you expected is missingIts feature may be off in src/custom/features.ts, or its check could not read its settings: look in the browser console for "could not be checked".
An app's row does not showLook in the browser console for "is listed twice": another row has its id. Check that its feature, if set, is on, and that pending returns an object, not true.
