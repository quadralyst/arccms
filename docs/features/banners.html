Banners

Two banners are yours to set: a message across the top of every page, and a site usage (cookie) banner at the bottom of every page outside the admin area. The admin area also shows a few status banners of its own.

What it is

Global messageAt the top of every page: public, member and admin. Not on an app's full-screen pages.Admin, Settings, Global Messages (/admin/settings/message)
Site usageAt the bottom of every page except admin pages, until the visitor accepts or rejects. On an app's full-screen page it waits for the next normal page.Admin, Settings, Site Usage (/admin/settings/site-usage)
Email not configuredOn the admin dashboard and, with the Signup forms feature on, the Signup Forms page, while email is offShown by itself (see Use it)

An app marks a page full-screen with data: { fullScreen: true } on its route, for a game or a kiosk screen (Add pages and routes).

Announcements are something else: with the Email marketing feature on, under Admin, Email, Announcements, an admin sends a message to chosen users as an in-app notification, and optionally by email. See Email marketing and Notifications.

Turn it on or off

Banners are always on: they are core, not a switchable feature. Each of your two banners is turned on with Enable Banner on its settings page and off with the Banner Enabled switch; both start switched off.

Set it up

Global message

  1. Open Admin, Settings, Global Messages and click Enable Banner.

  2. Write a heading and a message (both required).

  3. Optionally add a button label and URL. The button shows only when both are filled in, and opens the URL in a new tab.

  4. Pick a background style: Info Blue, Warning Amber, Success Green, Urgent Red, Ocean Blue or Ocean Teal. Check the preview, and click Save Settings.

Site usage

  1. Open Admin, Settings, Site Usage and click Enable Banner.

  2. Edit the message and the accept and reject button texts, or keep the defaults.

  3. Set the policy link. The default, /p/cookie-policy, opens the built-in page from public/_site/pages/cookie-policy.html; the built-in page is a sample that names Arc CMS and support@example.com, so point the link at your own policy, or write your own as src/custom/site/pages/cookie-policy.html, before launch.

  4. Pick a background style and click Save Settings.

Use it

Both banners update in open browsers as soon as you save: nobody has to reload.

  • The global message stays until you turn it off. Visitors cannot close it.
  • The site usage banner disappears for a visitor once they click accept or reject. The choice is kept in that browser only (local storage, key arc_site_usage), so they see it again in another browser or after clearing site data.
  • The email not configured banner shows while the email master switch is off (see Email engine). An admin can close it in that browser tab; it shows again in a new tab until email is turned on.
  • The Debug Provider banner stays while the Debug Provider is active, so a test setup is never taken for a live one.

The site usage banner records the visitor's choice and then hides; tracking does not depend on that choice. Google Analytics runs whether the visitor accepts or rejects (see Analytics). If your site must wait for consent before tracking, the banner alone does not provide it.

Both banners are drawn in the browser, not in the server-rendered HTML, so search engines and link previews do not see their text.

Extend it

The banners have no plug points. For a banner of your own (only in the member area, say, or with a dismiss button), build a component in the custom space (see Use the custom space) rather than changing these.

Troubleshooting

You seeWhy, and what to do
The site usage banner does not show for youYou already accepted or rejected in this browser, or you are on an admin page. Remove arc_site_usage from the site's local storage, or open a private window.
The global message has no buttonThe button needs both a label and a URL.
The email not configured banner keeps coming backEmail is off. Set up a provider and turn the master switch on (see Email engine).
