Templates

A template is a plain HTML file with data-arc-* attributes and {{ }} placeholders. Arc CMS fills it with an entry's data to build its page. No framework knowledge is needed.

For the step-by-step path of designing a site's templates, see Design templates. This page is the reference.

What it is

Each content type with public pages points at a template folder:

FileRendersRequired
list.htmlThe type's list page, /{type}No
detail.htmlOne entry, /{type}/{slug}No
partials.htmlA block of cards embedded in another app page (see Partials)No

A file a folder lacks is taken from the default folder, so a folder can hold just the one file it changes.

Arc CMS ships three folders in public/_site/templates/: default (used by any type without a folder of its own, so every type renders), articles and manuals. An app's folders go in src/custom/site/templates/. The build puts both together and serves them at /_site/templates/{folder}/{file}.html; a file in the app's folder at the same path as one of Arc CMS's replaces it. The folders offered in the admin are every folder the site has, listed by the build in /_site/site.json (see Use the custom space).

The same template is filled in two places, and both use the same attributes:

RendererWhenWhere the template comes from
Publishing (Cloud Functions)On publish, and on the seed. Writes the static pages Hosting serves.The same file, read from the live site at /_site/templates/. A folder the live site does not have stops the publish with a message (see Troubleshooting). Only when the live site cannot give the default folder's file (hosting off, or not deployed since /_site/ existed) is the copy of the default templates built into the functions used.
The app (browser)For pages not yet on Hosting, previews, and local runsThe file served by the app at /_site/templates/, the same one publishing reads once deployed.

A template is a fragment: no <html>, <head>, <body> or doctype. Publishing wraps it in a full document with the title, meta tags, structured data, language links and site stylesheets.

Turn it on or off

Templates are part of the Content feature (content). With content off there are no content pages, so templates are not used.

Set it up

  1. Copy a folder to start from, for example public/_site/templates/default/ to src/custom/site/templates/events/.

  2. Edit src/custom/site/templates/events/list.html and src/custom/site/templates/events/detail.html. Delete a file you do not change; the default's is used.

  3. In Content > Content types, edit the type and pick the folder under Content Template. Run the app locally and open /events to see the templates filled.

  4. Deploy Hosting (see Deploy), then rebuild the published pages so they use the new template:

    npm run seed:dev

    For production: npm run seed:prod. The full npm run deploy:dev and npm run deploy:prod run the seed at their end.

Publishing reads the template from the live Hosting site, not from your working copy. A template you changed locally shows in the app at once, but published pages keep the old one until Hosting is deployed and the pages are rebuilt (publish again, or run the seed).

To change the default look for every type without a folder, put your file at src/custom/site/templates/default/detail.html (or list.html, partials.html). Never edit public/_site/templates/: those are core files.

Use it

Attributes

SyntaxDoes
{{ key }}Inserts a value as text, in text or in any attribute (href="/{{ contentTypeSlug }}"). Dots reach inside objects ({{ author.name }}). A missing value is empty.
data-arc-bind="key"Fills the element. On <img> and <iframe> it sets src (and an image's alt to the title), on <a> href, on form fields the value, on <time> datetime and a formatted date. Anything else gets the value as its content; HTML is kept as HTML.
[innerHTML]="key"Sets the element's HTML (used for the body: [innerHTML]="content")
[src]="key", [href]="key"Sets that attribute from a value
data-arc-if="key"Removes the element when the value is empty, false or missing
data-arc-loop="name"Repeats the container's first child once per row; other children are dropped. An empty or unknown loop empties the container.
data-limit="N"On a loop container: at most N rows
data-arc-style-background="key"Sets the element's background color from a value
data-arc-t="key"Replaces the element's text with that UI string in the page's language; the English you wrote stays when there is no translation. data-arc-t-attr="placeholder:key" does the same for an attribute.

Loops run first, then bindings. Inside a loop row, the keys are the row's own ({{ title }} is the item's title). Loops do not nest: a loop inside a row is not filled.

data-arc-if checks whether a value is set, and a list with no rows still counts as set. Use the flags hasReferences and hasRelated for those lists, and CSS such as .cards:empty { display: none; } for an empty loop container.

UI string keys and translations are covered in Languages.

Special elements

ElementOn a published page
<arc-header></arc-header>Replaced with the site header
<arc-footer></arc-footer>Replaced with the site footer
<arc-search></arc-search>Replaced with the search box (see Search); removed when there is none
<arc-language-switcher></arc-language-switcher>Replaced with links to the page's other languages; removed on a one-language site

Use href="{{ langPrefix }}/{{ contentTypeSlug }}/{{ nextContent.slug }}" for a next link. A nextContent.url exists only when the app renders the page, so a published page built with it has an empty link.

Custom field bindings

A custom field binds by its stored key (events-price). On a detail page it also binds by its bare name (price); inside the items loop of a list or partial, use the stored key. The bare name never replaces a built-in: a field named "Title" does not shadow title. Some types add derived keys beside the stored value:

Field typeBindings (for a field keyed x)
iconx (class list, such as fa-solid fa-star), x_svg (inline SVG), x_label, x_name
colorx (hex), x_rgb (rgb(26, 115, 232)), x_rgb_values (26, 115, 232, for rgba())
image and the cover imagex plus x_s, x_m, x_l, x_xl
Any YouTube URL valuex_id, x_embed (youtube-nocookie.com), x_thumb (poster image)
infocard (loop)Rows: headline, info, icon or image, icon_svg, position
gallery (loop)Rows: image or video (with video_id, video_embed, video_thumb), caption
labelvalue (loop)Rows: label, value. The heading is x_heading, outside the loop.
maplocation (loop)Rows: label, address, lat, lng, map_embed (OpenStreetMap iframe URL), map_directions, map_view. The heading is x_heading.

Repeating fields render only on detail pages, not inside the items loop of a list or partial. The default detail template already loops fields with the keys gallery, details and locations, so fields with those keys render with no template work. It also loops info_cards, but a new field's key is made from its name with hyphens in place of spaces and underscores, so a new field cannot get that key: use a loop of your own, as below.

<section class="info-cards" data-arc-loop="info-cards">
    <article class="info-card">
        <img data-arc-if="image" data-arc-bind="image" alt="">
        <i data-arc-if="icon" class="{{ icon }}" aria-hidden="true"></i>
        <h3 data-arc-bind="headline">Headline</h3>
        <p data-arc-bind="info">Text</p>
    </article>
</section>

Image sizes

Every upload is stored at four sizes (see Media). Any image binding has one sibling per size, so a template can use a size the editor did not pick:

<img src="{{ coverImage_m }}"
     srcset="{{ coverImage_s }} 300w, {{ coverImage_m }} 600w, {{ coverImage_l }} 900w, {{ coverImage_xl }} 1200w"
     sizes="(max-width: 600px) 100vw, 600px" alt="{{ title }}">

The widths above are for the default maximum of 1200px. Unsplash photos get the sizes from Unsplash; an image pasted from elsewhere gets none.

Partials

partials.html renders a block of cards (such as "Latest articles") inside an app page, through the <arc-content-partials> component:

<arc-content-partials contentType="articles" [count]="4" sectionTitle="Latest Articles"></arc-content-partials>
InputDefaultMeaning
contentTypearticlesThe type's slug
count4How many entries
sectionTitleLatest UpdatesThe heading, bound as sectionTitle
templateFolderThe type's folderAnother folder's partials.html

Inside it, data-arc-loop="items" has the list page's item bindings except authorName, tagsDisplay, contentType and cat; an item's url is in the page's language. The section itself also has listUrl (the type's list page) and hasItems, so data-arc-if="hasItems" hides the block when the type has nothing published. A type without a partials.html of its own uses the default folder's cards. The component works in app pages, such as the home page; publishing removes it from content pages.

Header, footer and styles

WhatEditNotes
Header and footersrc/custom/site/header.html, src/custom/site/footer.html (else Arc CMS's public/_site/header.html, public/_site/footer.html)Plain HTML. The app renders them as they are, filling data-arc-t, the language of links, <arc-search> and <arc-language-switcher>. Publishing reads the same files from the live Hosting site at /_site/.

There is no admin screen for the list; change it in the Firestore console.
The site's own filessrc/custom/site/assets/, served at /site/Every one is listed with a hash in /_site/site.json. Published pages and the app's preview add it to links (versionSiteUrls in functions/src/shared/site-urls.ts and src/app/core/site/site-urls.ts: src, href, poster, srcset), and the build adds it to url() in the app's stylesheets (scripts/arc-site.mjs), so a changed file is never served from a year-long browser cache.

Icons from an icon field need Font Awesome in cssUrls; without it, bind x_svg instead of the class list.

Extend it

  • A new look for one type: a new folder, as in Set it up.
  • New attributes or bindings are a core change: the two renderers, functions/src/shared/template-hydration.ts and src/app/core/services/template-hydration.service.ts, must stay the same. See Keep core generic.

Templates have no Cloud Functions of their own; the content feature's functions render them (see Content).

Who can do what

Template files are changed by whoever can edit the repository and deploy Hosting. Choosing a type's folder is an admin action in the content type screen. Nothing about templates is kept in Firestore: earlier versions also read a templates collection and a Settings/partials document, set by hand in the Firebase console, and Arc CMS no longer reads either. Settings/site is admin only. See Security rules.

Troubleshooting

SymptomCause and fix
The folder is not in the Content Template listThe folder must sit directly in src/custom/site/templates/ and hold at least one of partials.html, list.html, detail.html. Restart npm run dev if it was running, or rebuild.
Publishing fails with "Template folder 'x' is not on the live site. Deploy the website, then publish again."The type names a folder the live site does not have yet, or its file there is not a template (a whole HTML document). The editor shows the message on the item. Deploy the website, then publish again.
The app logs "is not a template fragment"A file of the folder is a whole HTML document, or missing (a missing file answers with the app's own page, which is rejected). The app shows the default template instead. Make the file a fragment.
A binding renders emptyCheck the key on the content type's view page under Template Reference. A value is empty on a page built before the field was filled: publish again.
Placeholder text such as "Caption" shows on the pageText outside a loop's first child, or a binding with no value, keeps what you wrote. Put placeholder rows inside a loop, and guard optional parts with data-arc-if.
Changes show locally but not on the live siteDeploy Hosting, then rebuild the pages (npm run seed:dev or npm run seed:prod).
Icons show as empty boxesFont Awesome is not in cssUrls. Add it back, or bind the _svg form.
