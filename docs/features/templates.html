Templates

A template is a plain HTML file with data-arc-* attributes and {{ }} placeholders. Arc CMS fills it with an entry's data to build its page. No framework knowledge is needed.

For the step-by-step path of designing a site's templates, see Design templates. This page is the reference: the tables below are the full list of what a template can use.

What it is

Each content type points at a template folder. A type without public pages uses only the folder's partials.html, for its cards on the home page.

FileRendersRequired
list.htmlThe type's list page, /{type}No
detail.htmlOne entry, /{type}/{slug}No
partials.htmlA block of cards embedded in the home page (see Partials)No

A file a folder lacks is taken from the default folder, so a folder can hold just the one file it changes.

Arc CMS ships three folders in public/_site/templates/: default (used by any type without a folder of its own, so every type renders), articles, manuals and info (the standard pages, see Standard pages). An app's folders go in src/custom/site/templates/. A folder name uses lowercase letters, digits, hyphens and underscores, and starts with a letter or digit (case-studies, blog_2); a folder named otherwise is not served, and npm run dev warns about it. The build puts both sets together and serves them at /_site/templates/{folder}/{file}.html; a file in the app's folder at the same path as one of Arc CMS's replaces it. The folders offered in the admin are every folder the site has, listed by the build in /_site/site.json (see Use the custom space).

The same template is filled in two places, and both use the same attributes:

RendererWhenWhere the template comes from
Publishing (Cloud Functions)On publish, on Republish website, and on the seed. Writes the static pages Hosting serves.The same file, read from the live site at /_site/templates/ and kept until a deploy changes it (the functions check /_site/site.json, which holds a hash of every file, at most every 10 seconds). A folder the live site does not have, or a file of it that is not a template, stops the publish with a message (see Troubleshooting). When the live site cannot give the default folder's file (hosting off, not deployed since /_site/ existed, or the file is not a template), the copy of Arc CMS's default templates built into the functions is used.
The app (browser)For pages not yet on Hosting, previews, and local runsThe file served by the app at /_site/templates/, the same one publishing reads once deployed. A folder the site does not have, or a list or detail file that is not a template, falls back to the default folder's. A partials.html that is not a template shows nothing, and a default folder file of your own that is not a template leaves the page loading.

A template is a fragment: no <html>, <head>, <body> or doctype. Only real tags count, in the file's first 2,000 characters: a comment, <style> or <script> that mentions <head> is fine. Publishing wraps it in a full document with the title, meta tags, structured data, language links and site stylesheets; see What publishing puts around your template.

Turn it on or off

Templates are part of the Content feature (content). With content off there are no content pages, so templates are not used.

Set it up

  1. Copy a folder to start from, for example public/_site/templates/default/ to src/custom/site/templates/events/.

  2. Edit src/custom/site/templates/events/list.html and src/custom/site/templates/events/detail.html. Delete a file you do not change; the default's is used.

  3. In Content > Content types, edit the type and pick the folder under Content Template. Run the app locally and open /events to see the templates filled.

  4. Deploy Hosting (see Deploy), then rebuild the published pages so they use the new template:

    npm run seed:dev

    For production: npm run seed:prod. The full npm run deploy:dev and npm run deploy:prod run the seed at their end. Republish website in Content > Content types also rebuilds every page.

Publishing reads the template from the live Hosting site, not from your working copy. A template you changed locally shows in the app at once, but published pages keep the old one until Hosting is deployed and the pages are rebuilt. Publishing sees a deploy within about 10 seconds.

To change the default look for every type without a folder, put your file at src/custom/site/templates/default/detail.html (or list.html, partials.html). Never edit public/_site/templates/: those are core files.

Use it

Attributes

SyntaxDoes
{{ key }}Inserts a value as text, in text or in any attribute (href="/{{ contentTypeSlug }}"). Dots reach inside objects ({{ author.name }}) and lists ({{ tags.0 }}). A missing value prints nothing. See Syntax details.
data-arc-bind="key"Fills the element. On <img> it sets src, and alt to the data's title when there is one (replacing the alt you wrote). On <iframe> it sets src, on <a> href (the link text stays), on <input>, <textarea> and <select> the value. On <time>, datetime gets the value as it is and the text becomes a long date in the page's language, such as "January 5, 2026" (English in the app) (a value that is not a date is printed as it is). Any other element gets the value as its content: a value that looks like HTML is kept as HTML, anything else is text. With no value, the element keeps what you wrote.
[innerHTML]="key"Sets the element's HTML (used for the body: [innerHTML]="content"). Reads top-level keys only: [innerHTML]="author.bio" does not work. With no value, the element keeps what you wrote.
[attr]="key"Sets any attribute from a value: [src], [href], [title], [data-id]. Dots work. With no value, the attribute is not added.
data-arc-if="key"Removes the element when the value is missing, empty, 0 or false. Dots work (data-arc-if="author.name").
data-arc-loop="name"Repeats the container's first child once per row; other children are dropped. An empty or unknown loop empties the container.
data-limit="N"On a loop container: at most N rows. 0, or anything that is not a number, means no limit.
data-arc-style-background="key"Adds background-color from the value and color: #333 to the element's style
data-arc-t="key"Replaces the element's content with that UI string, as plain text, in the page's language. The content you wrote stays when there is no translation.
data-arc-t-attr="placeholder:key"The same for an attribute. Several pairs are separated by commas: data-arc-t-attr="placeholder:search_hint, title:search_title".
data-arc-t-paramsA JSON object of values for {{ }} in the translated string, such as data-arc-t-params='{"site": "Acme"}'. A {{ }} it does not fill is left for the template's data.
class="arc-skeleton"A loading look in the app. The class is removed from an element once it is filled; see Syntax details.

A template is filled in this order: UI strings (data-arc-t) first, then site info (data-arc-site, below), then loops, then the page's own bindings. So a translated string may itself hold a placeholder such as {{ contentType }}, and a loop's row is translated once, before it is repeated. UI string keys and translations are covered in Languages.

Site info

The site's own details, typed once in Settings, About, print on any page with data-arc-site: in the header, the footer, the home page, every template (list, detail and partials) and static pages, both on published pages and in the app. A change in About republishes every page that uses them.

SyntaxDoes
data-arc-site="name"The site name. description is the About description.
data-arc-site="email"The public contact email. On an <a> it also sets href to mailto:.
data-arc-site="phone"The public phone, as typed. On an <a> it also sets href to tel: with only the digits and a leading +.
data-arc-site="address"The address, its line breaks kept
data-arc-site="logo"On an <img>: the logo as src, and the site name as alt when you wrote none
data-arc-site="year"The current year, for a copyright line. Always has a value.
data-arc-site-if="key"Keeps the element only when the site has that value, so a label or an icon goes with it. Besides the keys above it takes social (any social link), pages (any published standard page) and contact (any email, phone, address or social link, for a "How to reach us" block).
data-arc-site-loop="social"Repeats the container's first child once per social link, in the order they were typed. Each row has {{ url }}, {{ platform }} (instagram, x, linkedin; link for a site it does not know), {{ label }} (Instagram; the host name for an unknown site) and {{ icon }} (Font Awesome classes).
data-arc-site-loop="pages"Repeats the first child once per published standard page (About, Contact, the policies), in their arranged order. Each row has {{ url }} and {{ title }}, titled in the page's language.

An element bound to a value the site does not have is removed. The social links are the Social and profile links of About, one URL per line; the platform is read from each address. Known sites are Facebook, Instagram, X, LinkedIn, YouTube, GitHub, TikTok, Pinterest, Threads, WhatsApp, Telegram and Medium.

<p data-arc-site-if="phone"><i class="fa-solid fa-phone"></i> <a data-arc-site="phone"></a></p>
<ul data-arc-site-loop="social">
    <li><a href="{{ url }}" aria-label="{{ label }}"><i class="{{ icon }}"></i></a></li>
</ul>

Syntax details

CaseWhat happens
Characters in a keyLetters, digits, _, - and .. Spaces inside the braces are optional: {{title}} and {{ title }} are the same, and {{ events-price }} works.
Filters and expressionsNone. {{ title | upper }}, {{ a + b }} and {{ title || 'Untitled' }} are printed exactly as written. Change a value with CSS (text-transform) or a script.
Numbers and flagsPrinted as text: 0 prints "0", a flag prints "true" or "false".
ListsPrinted as their items joined by commas with no space: a detail page's {{ tags }} prints "News,Tips". Reach one item by its position from 0: {{ tags.0 }}; in a card, where tags are objects, {{ tags.0.name }}.
ObjectsPrint [object Object]. Name a field inside: {{ author.name }}, not {{ author }}.
Escaping{{ }} in text and in attributes is escaped, so a title holding <b> shows those characters. Inside <script> and <style> it is inserted raw: var title = "{{ title }}"; breaks on a title with a quote mark, so read values from the page's HTML in a script instead. [innerHTML], and a data-arc-bind value that looks like HTML, are inserted as HTML, unescaped.
data-arc-ifA yes or no test of one value. Missing, empty text, 0 and false remove the element; anything else keeps it, including a list with no rows and an object. There is no negation or comparison: data-arc-if="!coverImage" or data-arc-if="lang == 'hi'" is read as a key, finds nothing and always removes the element. To show something only when a value is empty, use a flag such as hasRelated or CSS such as .cards:empty + .empty-state.
Inside a loop row{{ }} and data-arc-if see only the row's own keys: {{ title }} is the row's title, and a page key the row does not have prints nothing. A data-arc-bind the row cannot fill is filled afterwards from the page's data.
A loop inside a loop rowNot supported: the inner container is emptied. For a card's tags use tagsHtml or tagsDisplay.
The same loop name twiceBoth containers get the same rows, built from the first container's row and its data-limit; the second container's own row is ignored.
data-arc-t with an icon insideA translation replaces everything inside the element with text, so an icon inside it is lost. Keep icons outside: <i class="fas fa-arrow-right"></i> <span data-arc-t="read_more">Read</span>.
arc-skeletonRemoved from an element when {{ }} in its own text, [innerHTML] or data-arc-bind fills it. The app styles it, and every unfilled data-arc-bind, as a grey shimmer with hidden text. Published pages have no style for it.

Custom field bindings

A custom field binds by its stored key (events-price) and by its short key, the name without the type slug (price), on detail pages and inside the items loop of lists and partials. So one template can serve several types. The short key never replaces a built-in: a field named "Title" does not shadow title. Some types add derived keys beside the stored value:

Field typeBindings (for a field keyed x)
iconx (class list, such as fa-solid fa-star), x_svg (inline SVG), x_label, x_name
colorx (hex), x_rgb (rgb(26, 115, 232)), x_rgb_values (26, 115, 232, for rgba())
image and the cover imagex plus x_s, x_m, x_l, x_xl
Any YouTube URL valuex_id, x_embed (youtube-nocookie.com), x_thumb (poster image)
infocard (loop)Rows: headline, info, icon or image, icon_svg, position
gallery (loop)Rows: image or video (with video_id, video_embed, video_thumb), caption
labelvalue (loop)Rows: label, value. The heading is x_heading, outside the loop.
faq (loop)Rows: question, answer (plain text), answer_html (the answer with blank lines as paragraphs and web addresses as links; bind with data-arc-bind="answer_html"). The heading is x_heading.
maplocation (loop)Rows: label, address, lat, lng, map_embed (OpenStreetMap iframe URL), map_directions, map_view. The heading is x_heading.

Repeating fields render only on detail pages, not inside the items loop of a list or partial. The default detail template already loops fields with the keys gallery, details, faq and locations, so fields with those keys render with no template work. It also loops info_cards, but a new field's key is made from its name with hyphens in place of spaces and underscores, so a new field cannot get that key: use a loop of your own, as below.

<section class="info-cards" data-arc-loop="info-cards">
    <article class="info-card">
        <img data-arc-if="image" data-arc-bind="image" alt="">
        <i data-arc-if="icon" class="{{ icon }}" aria-hidden="true"></i>
        <h3 data-arc-bind="headline">Headline</h3>
        <p data-arc-bind="info">Text</p>
    </article>
</section>

Image sizes

Every upload is stored at four sizes (see Media). Any image binding has one sibling per size, so a template can use a size the editor did not pick:

<img src="{{ coverImage_m }}"
     srcset="{{ coverImage_s }} 300w, {{ coverImage_m }} 600w, {{ coverImage_l }} 900w, {{ coverImage_xl }} 1200w"
     sizes="(max-width: 600px) 100vw, 600px" alt="{{ title }}">

The widths above are for the default maximum of 1200px; they follow the maximum set in Settings, Misc. Unsplash photos are resized by Unsplash to the same limits; an image pasted from elsewhere gets none.

Header, footer and styles

Extend it

  • A new look for one type: a new folder, as in Set it up.
  • New attributes or bindings are a core change: the two renderers, functions/src/shared/template-hydration.ts and src/app/core/services/template-hydration.service.ts, must stay the same. See Keep core generic.

Who can do what

Template files are changed by whoever can edit the repository and deploy Hosting. Choosing a type's folder is an admin action in the content type screen. Nothing about templates is kept in Firestore: earlier versions also read a templates collection and a Settings/partials document, set by hand in the Firebase console, and Arc CMS no longer reads either. Settings/site is admin only. See Security rules.

Troubleshooting

SymptomCause and fix
The folder is not in the Content Template listThe folder must sit directly in src/custom/site/templates/, have a name of lowercase letters, digits, hyphens and underscores that starts with a letter or digit, and hold at least one of partials.html, list.html, detail.html. Restart npm run dev if it was running, or rebuild.
Publishing fails with "Template folder 'x' is not on the live site. Deploy the website, then publish again."The type names a folder the live site does not have yet, or its file there is not a template (a whole HTML document). The editor shows the message on the item. Deploy the website, then publish again.
The app logs "is not a template fragment"A file of the folder is a whole HTML document, or missing (a missing file answers with the app's own page, which is rejected). For a list or detail file the app shows the default template instead; a partial shows nothing; a default folder file of your own leaves the page loading. Make the file a fragment.
A binding renders emptyCheck the key against the tables on this page. The admin's Template Reference on a content type's view page lists the same bindings by page, and the type's own fields with the snippet each needs. A binding that works on a detail page may not exist in a card (summary, author.name), and repeating fields render on detail pages only. A value is also empty on a page built before the field was filled: publish again.
Placeholder text such as "Caption" shows on the pageAn element with data-arc-bind whose value is missing keeps the text you wrote (in the app it shows as a grey shimmer). Loops do the opposite: they keep only the first child as the row and drop the rest. Use {{ }}, which prints nothing when the value is missing, or guard optional parts with data-arc-if.
Changes show locally but not on the live siteDeploy Hosting, then rebuild the pages (npm run seed:dev or npm run seed:prod).
A data-arc-site element is missing from the pageThe value is empty in Settings, About, so the element was removed. Fill it in; the pages that use it are republished.
Icons show as empty boxesFont Awesome is not in cssUrls. Add it back, or bind the _svg form.
