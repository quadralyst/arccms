Glossary

The words Arc CMS and these docs use, each explained in a line or two. Follow the link for the whole story.

TermMeaning
Admin-only sign-inAn install setting under which onboarding turns sign-ups off once the first admin exists, so only people an admin adds can sign in. On by default for the backend profile. See Configuration keys.
AnnouncementAn in-app notification an admin sends to chosen users, optionally also as an email. Part of email marketing. See Email marketing.
App audienceThe users of the app Arc CMS serves, read from a collection of that app (or from Arc CMS's own users), so emails and lists can reach them without copying them into contacts by hand. See App audience.
arccms- prefixEvery Arc CMS Cloud Function is deployed as arccms-<name>, and an app's own as arccms-custom-<name>, so they never clash with another app's functions in the same project. See Cloud Functions.
AudienceThe people you can email: contacts, grouped in lists, with tags and custom fields. A switchable feature. See Audience.
AutomationsRules, set under Settings, Automations, that turn events in the app into notifications, emails or list changes. See Automations.
Brand kitThe shared look of every branded email: logo, colors, font, footer text, postal address and social links. See Email engine.
BroadcastOne email sent to the contacts of chosen lists, now or at a set time. See Email marketing.
ClaimA value Firebase Auth carries in a person's sign-in token. Arc CMS sets arccms_role (their role) and arccms_uid (the id of their users record); the security rules and functions read them. See Roles and claims and Follow the account contract.
ComposerThe block editor for email templates in the admin. See Email engine.
ContactOne person in the audience, known by email address, with consent, tags, list memberships and custom fields. See Audience.
Content typeA kind of content, such as a blog post, with its fields and template. Each type keeps its drafts and its published items in collections of its own. See Define content types.
CoreArc CMS's own files: everything outside the custom space. An app built on Arc CMS never edits them, so updates merge cleanly. See Core and custom.
Custom spaceThe files that belong to the app built on Arc CMS: src/custom/, functions/src/custom/, firestore.app.rules, storage.app.rules and firestore.app.indexes.json. See Use the custom space.
Drip campaignA sequence of emails sent to each member of a list, step by step, starting when they join. See Email marketing.
Email logThe record of one email: every send is queued as a document in EmailLogs, then sent, retried or skipped. See Email engine.
EntitlementThe premium access a purchase gives a person, written on their user record: a tier and, for a subscription, when it ends. See Premium entitlements.
FeatureOne of the ten parts of Arc CMS an app can turn on or off by id in src/custom/features.ts. Everything else is always on. See Feature ids.
IndexNowA service Arc CMS notifies after each publish, so search engines that use it pick up changed pages quickly. Part of seo. See SEO and discoverability.
Install configThe optional file arccms.config.json that says, per Firebase project, which database, hosting site and bucket Arc CMS uses. See Configuration keys.
Install profilestandalone when Arc CMS has its Firebase project to itself, backend when it shares the project with another app and so needs its own database, site and bucket. See Sharing a Firebase project.
ListA group of contacts that emails are sent to. Each signup form has its own list. See Audience.
llms.txtA file at the site root that lists the site's pages, linking their Markdown twins, for AI tools to read. Published by seo. See SEO and discoverability.
Markdown twinA Markdown copy of each published content page, next to the HTML page, for AI tools. See SEO and discoverability.
Merge tagA placeholder such as ##NAME## in an email, replaced for each recipient when it is sent. See Email merge tags.
Named databaseA Firestore database other than the project's (default) one, such as arccms. Arc CMS uses one when it shares a project with another app. See Sharing a Firebase project.
PublishTurning content into static HTML files on Firebase Hosting. A Cloud Function does it from a queue of publish jobs. See Content.
PWAProgressive web app: a site people can install on their phone or computer like an app. The pwa feature, off by default. See Installable app (PWA).
RoleWhat a person may do: admin, or user for everyone else. The rules also know editor (content staff), which nothing in the admin area grants. See Users and roles.
Signup formA form that collects sign-ups, with a verification code, a welcome email, referrals and a leaderboard. The code and the database call it a waitlist (Waitlists). See Signup forms.
Static pagesHTML pages kept as files in src/custom/site/pages/ (Arc CMS's samples in public/_site/pages/) and served at /p/{name}, such as the privacy policy. npm run seed:dev and seed:prod publish them to Hosting again, with every published content page. See Write static pages.
Switchable featureSee Feature.
Targeted deployA deploy of only the functions that changed, named one by one, instead of the whole codebase. See Deploy only what changed.
UpstreamThe Arc CMS repository an app was copied from, added as the git remote upstream. npm run check:core compares with it, and updates are pulled from it. See Keep core untouched.
WaitlistThe code's name for a signup form. See Signup form.
