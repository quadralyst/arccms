Cloud Functions

Every Cloud Function Arc CMS deploys, grouped by area: what kind it is, who may call it or what starts it, and what it does. Use it to find the function behind a screen, or the one to deploy after a change.

How a function is named

functions/src/index.ts exports every function in one group, arccms. A function exported as sendTestEmail therefore deploys as arccms-sendTestEmail. The rule is arcFunctionName() in functions/src/function-names.ts, and the functions belong to the arccms codebase in firebase.json.

  • The browser calls a function by its plain name through arcCallable() in src/app/core/config/arc-functions.ts, which adds the prefix.
  • An HTTP function is reached at its arccms- name, for example arccms-handleUnsubscribe.
  • An app's own functions in functions/src/custom/ deploy as arccms-custom-<name> and are not listed here. See Write your own Cloud Functions.

To deploy one function instead of all of them, see Deploy only what changed.

Which functions are deployed

Core functions are listed in functions/src/all.ts and always deploy. A switchable feature's functions are listed in functions/src/features/, one file per feature. Before every functions build, scripts/arc-features.mjs reads src/custom/features.ts and writes a generated list of the feature files whose features are on, which functions/src/all.ts exports.

  • A full functions deploy with a feature off deletes that feature's functions.
  • functions/src/features/search+content.ts deploys only when both search and content are on.
  • The data feature has no functions.

The feature ids are in Feature ids.

Who may call a function

Each callable checks its caller at the top of its handler. The tables below use these words:

WordMeaning
AdminThe caller's arccms_role claim is admin (functions/src/users/claims.ts). Some functions also read the claim from the account itself (functions/src/search/auth.ts), so a fresh claim works before the token refreshes.
Signed inAny signed-in account, whatever its role.
Own recordSigned in, with a users record of their own (requireOwnRecord() in functions/src/auth/accounts.ts), and not a locked app account (App accounts). Only refreshMyClaims also takes a locked app account.
PublicNo sign-in needed. Where a limit is given, it counts per caller (a hash of the IP address) or per address, in a fixed hour.

Roles and claims are explained in Roles and claims.

Every Firestore trigger listens on the install's own database, ARC_DATABASE_ID (arcDocument() in functions/src/arc-config.ts). Every schedule runs in UTC.

A trigger's database is fixed when it is deployed: after changing the database, deploy the functions again (see Configuration keys).
