Configuration keys

Arc CMS reads its settings from three places: the install config arccms.config.json, a few environment variables, and the starter files of the custom space. This page lists every key.

The install config: arccms.config.json

The optional file arccms.config.json at the repository root says how Arc CMS sits in each Firebase project: which database, hosting site and bucket it uses. Without it every value is the default, which is right for a site that has a Firebase project to itself. Copy arccms.config.example.json to start:

{
  "profile": "standalone",
  "projects": {
    "your-project-id": {
      "profile": "backend",
      "databaseId": "arccms",
      "hostingSite": "your-project-arccms",
      "storageBucket": "your-project-arccms",
      "storagePrefix": ""
    }
  }
}

Keys at the top level apply to every project; the keys under projects override them for one project. Nothing reads the file directly at run time: npm run arc:configure turns it into src/environments/arc-install.ts, functions/.env.<projectId> and, when needed, firebase.<projectId>.json, and the guided npm run deploy does the same before each deploy. How to set it up is on Configure a project and Sharing a Firebase project.

Keys

KeyType and defaultEffect
profile"standalone" or "backend". Default "standalone".standalone: Arc CMS has the project to itself. backend: it shares the project with another app, so it must have its own databaseId (not (default)), hostingSite and storageBucket, adminOnlySignIn defaults to yes, and arc:configure prints the commands that create those resources.
projectsObject keyed by Firebase project id. Default none.Settings for one project, laid over the top-level keys. arc:configure --project=<alias or id> resolves an alias from .firebaserc to the id.
databaseIdString. Default "(default)".The Firestore database Arc CMS reads and writes. Lowercase letters, digits and hyphens, 3 to 63 characters, starting with a letter; or (default). Written to arc-install.ts for the browser, to ARC_DATABASE_ID for the functions, and to the generated Firebase config for rules and index deploys.
hostingSiteString. Default the project id (the project's first site).The Firebase Hosting site the static pages are published to. "none" turns Hosting off: nothing is published and a deploy includes no Hosting. Written to ARC_HOSTING_SITE, the generated Firebase config and src/environments/arc-install.ts (so the admin in npm run dev can compare your site files with the live ones).
storageBucketString, without gs://. Default the bucket in the app's Firebase config.The Storage bucket for uploads. Written to arc-install.ts, ARC_STORAGE_BUCKET and the generated Firebase config. With a named database but no bucket of its own, Arc CMS deploys no Storage rules, because a bucket has one rules file and the other app's would be replaced.
storagePrefixString. Default "" (the bucket root).A folder every new upload goes under, such as "arccms/". Must be one folder ending in a slash. Written to arc-install.ts and ARC_STORAGE_PREFIX.
adminOnlySignIn"yes" or "no". Default "yes" for backend, else "no".Onboarding turns sign-ups off once the first admin exists. Written to arc-install.ts. See Sign-in methods.
appUsersDatabaseString. Default "(default)".The database that holds the host app's users, for the App audience. Written to ARC_APP_USERS_DATABASE. See App audience.
appUsersPathString, <collection>/{id}. Default a collection nothing writes to.The host app's user documents, one top-level collection, such as users/{uid}. Written to ARC_APP_USERS_PATH.
appUsers"own". Default not set.The App audience is this install's own users collection; sets appUsersDatabase to databaseId and appUsersPath to users/{id}.
regionString, a Firestore or Storage location. Default not set.The location in the setup commands arc:configure prints for a backend install. When functionsRegion is not set, it also chooses that: the region next to this location.
functionsRegionString, a Cloud Functions region. Default "us-central1".Where the functions run: next to the database. The first functions deploy sets it to the database's region (see Regions). Written to ARC_FUNCTIONS_REGION for the functions, to arc-install.ts for the website, and onto the Hosting rewrites in the generated Firebase config.

Every value is a string. arc:configure drops any other type without a word, so "adminOnlySignIn": true is ignored and the default applies. Write "yes" or "no", or use the flag: npm run arc:configure -- --admin-only-sign-in=yes.

Each key has a flag that sets it for one project and writes the file for you: --profile, --database, --site, --bucket, --prefix, --region, --functions-region, --app-users-database, --app-users-path, --app-users, --admin-only-sign-in. Add --dry-run to see what would change.

Environment variables

The Cloud Functions read their install settings from functions/.env (the committed defaults) overridden by functions/.env.<projectId>. arc:configure writes the ARC_ lines of the project's file and keeps every other line, so set these through arccms.config.json, not by hand.

VariableDefaultRead by and effect
ARC_DATABASE_ID(default)The functions: the database they use, and, as a deploy-time parameter, the database every Firestore trigger listens on. Always written, because a non-interactive deploy refuses a parameter with no value.
ARC_FUNCTIONS_REGIONus-central1The functions, as a deploy-time parameter: the region every function runs in (functions/src/region.ts), and the address the published search box calls. Always written, like ARC_DATABASE_ID.
ARC_HOSTING_SITEThe project idThe functions and the seed scripts: the Hosting site pages are published to. none turns publishing off.
ARC_STORAGE_BUCKETThe project's default bucketThe functions: the bucket Arc CMS files live in, such as the folder deleted with an account.
ARC_STORAGE_PREFIXEmpty (bucket root)The functions: the upload folder, ending in /.
ARC_APP_USERS_DATABASE(default)The functions, as a deploy-time parameter: the database of the host app's users.
ARC_APP_USERS_PATH_arccms_app_users_not_configured/{id}The functions, as a deploy-time parameter: the host app's user documents, watched by the App audience trigger. The default is a path nothing writes to.
PORTVite's own (5173)npm run dev: the dev server's port, so a second one can run beside the first.
USE_DEV_ENVNot setnpm run build: true builds for production with src/environments/environment.ts instead of src/environments/environment.prod.ts. deploy:dev sets it.
GCLOUD_PROJECTThe alias's project in .firebasercnpm run seed:dev and seed:prod: the project to seed, when set.

A trigger's database is fixed when the function is deployed, from ARC_DATABASE_ID in the dotenv files. Change databaseId, run arc:configure, then deploy the functions again, or the triggers keep listening on the old database.

Custom space starter exports

An app configures Arc CMS through the starter files of the custom space. Arc CMS ships each one empty and never edits it again. See Use the custom space.

ExportFile and typeWhat it does
CUSTOM_FEATURESsrc/custom/features.ts, FeatureChoice: { on?: FeatureId[]; off?: FeatureId[] }The features the app turns on (pwa) or off. Empty: every feature except pwa. See Feature ids.
CUSTOM_ROUTESsrc/custom/routes.ts, Angular RoutesThe app's own routes, added after Arc CMS's explicit routes and before the file-based pages, so an app page cannot replace a core page. See Add pages and routes.
CUSTOM_NAVsrc/custom/nav.ts, MenuItem[]The app's items in the admin menu, shown before Profile. Each item takes label, labelKey, route or externalUrl, icon, subItems, allowRoles and feature. See Add admin menu items.
CUSTOM_HOMEsrc/custom/home.ts, HomePages: role to pathWhere each role lands after signing in, laid over the defaults (admin: /admin/dashboard, everyone else: /user/dashboard). '*' covers roles not listed, but not admin, which keeps its default unless you list it. A sign-in that started from a page returns there instead. See Build the member area.
CUSTOM_USER_DASHBOARDsrc/custom/user-dashboard.ts, UserDashboardLoader | nullA loader for the app's own page at /user/dashboard. null shows Arc CMS's dashboard. See Build the member area.
CUSTOM_PWAsrc/custom/pwa.ts, Partial<PwaConfig>The installable app's name, shortName, description, themeColor, backgroundColor and startUrl, laid over the defaults in src/app/core/pwa/pwa-config.ts. Used only when pwa is on. See Make it installable.
SEARCH_COLLECTIONSfunctions/src/custom/search-sources.ts, string[]Collections the app makes searchable besides content. Each gets its own trigger, so adding or removing one needs a functions deploy; fields and results are set in the admin under Settings, Search. See Search.
CUSTOM_SEARCH_SOURCESfunctions/src/custom/search-sources.ts, SearchSource[]Search sources written in code, for what the settings cannot express. A ready-made one for products is in functions/src/search/sources/products.ts. See Search.

The other starter files have no settings to export: src/custom/pages/ (file-based pages), src/custom/i18n/ (translations), src/custom/styles.css (global styles), functions/src/custom/index.ts (the app's Cloud Functions, deployed as arccms-custom-<name>) and functions/src/custom/public-callables.txt (the app's callables, one per line, for the post-deploy access check).
