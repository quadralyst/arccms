What members see

A signed-in person who is not an admin uses the member area. It is a small sidebar layout with the site's name, the person's own pages, and the same menu for every install until an app changes it. It follows the member's language when the app declares one (see Member languages).

The menu

The member area starts at /user/dashboard. Its menu shows these items, in this order. The payment items appear only when the payments feature is on.

HomeBack to the app's own home page. It appears only when an app sets a home page other than the dashboard.An app's custom home

With payments on, the sidebar also shows the member's credit balance.

Signing in and signing up

People sign in and sign up on the same page, with the methods the site has switched on (see Sign-in methods). A sign-in that started from a protected page returns there afterwards. Otherwise each role lands on its home: admins on /admin/dashboard, everyone else on /user/dashboard, unless the app sets another home.

Making it the app's own

An app built on Arc CMS decides what members land on, without editing core files:

  • The app's own page at /user/dashboard, set with CUSTOM_USER_DASHBOARD.
  • A different home for a role, set with CUSTOM_HOME.

Both are explained in Build the member area.
