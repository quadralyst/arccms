Word the sign-up notice

Every sign-up form carries a notice: "By signing up, you agree to our Terms of Service and Privacy Policy, and to receive emails from us." A contact form carries a line of its own: "We use your details only to reply. Privacy Policy". Arc CMS writes both in English and Hindi. In src/custom/notices.ts you write them your way, in every language your app uses, with links to wherever your terms live.

Where the notice shows

One file words the notice everywhere it appears:

  • the account sign-up page and the setup wizard;
  • the signup forms on your website (data-waitlist-form, see Add forms to your site), both in the app and on the published pages;
  • the contact form's line (data-arc-contact-form, see Contact form).

A form that brings its own data-legal-notice or data-contact-notice element keeps it, as before.

The file

Arc CMS ships src/custom/notices.ts empty, and while it is empty every notice reads exactly as Arc CMS words it. It is yours: Arc CMS never changes it again, and npm run check:core counts it as your own code. CUSTOM_NOTICES holds two notices, each a text per language code:

import type { CustomNotices } from '../shared/utils/notice-text';

export const CUSTOM_NOTICES: CustomNotices = {
  signup: {
    en: 'By signing up, you agree to the {terms} and {privacy} of Acme Ltd. We will also email you news; you can stop it at any time.',
    // Keep in step with the German pages on acme.example.
    de: 'Mit der Anmeldung akzeptierst du die [AGB]({terms}), den [Datenschutz]({privacy}) und die [Cookie-Richtlinie](/p/cookies) der Acme GmbH. Fragen? [Schreib uns](mailto:legal@acme.example).',
  },
  contact: {
    en: 'We use your details only to reply. [How we handle them](https://acme.example/privacy)',
    de: 'Wir nutzen deine Angaben nur für die Antwort. [Datenschutz]({privacy})',
  },
};

Fill only the notice you want to change: a notice with no text for the page is Arc CMS's own. The file is code, so you can keep a note beside a text, as above, or build a text from a constant you share between languages.

Links and placeholders

A text is plain words. It has no HTML; a <b> shows as those letters. Two things inside it are not plain:

  • A link, written [the words](where it goes), as many as you need. It may go to a path on your site (/p/cookies, /info/terms), an https: address or a mailto: address. Anything else, such as http: or javascript:, is shown as plain words.
  • A placeholder: {terms} or {privacy}. Alone, it shows "Terms of Service" or "Privacy Policy" in the page's language (Arc CMS has English and Hindi; on a website page, the legal_terms and legal_privacy keys of the page's strings file), linked to your terms or privacy page. As a link's target, [AGB]({terms}), your own words link to that page. In a language Arc CMS has no label for, use the link form.

Your terms and privacy pages are the published standard pages /info/terms and /info/privacy-policy, else your own static pages at /p/terms and /p/privacy-policy (Write static pages). Until you have one, its placeholder shows the words without a link. To link a page somewhere else, such as your company's website, write the address: [Terms of Service](https://acme.example/terms).

Which language shows

For a page in a language, the notice is the first of these the file has:

  1. the page's language, as written (de-ch), then without its region (de), so a Swiss German page finds your German text;
  2. the site's default language (Settings, Localization);
  3. your English text;
  4. Arc CMS's own notice.

Language codes are not case sensitive: de-CH and de-ch are the same. The sign-up page and the setup wizard use the language they are shown in, on the sign-up page the one the person chose for the app (Member languages); a website page uses the page's own.

Mistakes stop the build

npm run dev and npm run build check the file before they start and stop on a mistake, naming the notice, the language and what is wrong:

The app's notices need fixing (docs/app/sign-up-notice.html):
  src/custom/notices.ts: signup.de: [AGB](javascript:void0) links to "javascript:void0"; a link goes to a path on the site (/p/terms), an https: address or a mailto: address.

The check finds a link target that is not allowed, a link with no words, an unknown placeholder such as {cookies}, a link or placeholder left open, a language code that is not one, an empty text and a notice other than signup and contact. So no visitor sees a broken link or a placeholder.

Style it

The text carries words and links only, so its look stays in one place for every language: your CSS. The sign-up notice has the class .arc-legal-notice on the sign-up page, the setup wizard and every signup form, and the contact line has .arc-contact-notice. Their size, spacing and link look come from these variables, set in src/custom/site/site.css, which the website and the sign-in pages load:

VariableWhat it setsArc CMS's value
--arc-notice-font-sizeThe size of the words0.8rem
--arc-notice-line-heightThe line height1.4
--arc-notice-opacityHow faint the notice is, on website forms0.75
--arc-notice-marginThe space around it, on website forms0.5rem 0
--arc-notice-link-colorThe links' colourthe notice's own
--arc-notice-link-decorationThe links' underlineunderline
 
:root {
  --arc-notice-font-size: 0.85rem;
  --arc-notice-link-color: #0b5cad;
}
.arc-legal-notice { font-weight: 500; }

Anything else, such as weight or alignment, goes on the classes. On the sign-up page the notice's colour is --arc-sign-in-muted-color (see Brand the sign-in page).

Deploy and test it

The app reads the file when it is built, and the build serves its notices at /_site/notices.json, where publishing reads them. Deploy the website with npm run deploy: the sign-up pages change at once, and every published page is published again with the new words. No function needs deploying.

To see it, open the sign-up page with the app in each of your languages, and a page with a signup form. Arc CMS's own tests prove the language order, the links and that a published page says the same words as the app; to keep your wording from changing by accident, add a spec of your own under src/custom/ that imports CUSTOM_NOTICES (see Use the custom space).
