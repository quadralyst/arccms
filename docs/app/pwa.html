Make it installable

Your app can be installed from the browser to a phone's home screen or a computer, and open like an app. It takes one switch, a name and one icon.

What people see, the update bar and the install numbers are in Installable app (PWA). This page is the setup.

Turn it on

  1. Switch on the feature in src/custom/features.ts. The PWA is the one feature that is off until you ask for it:

    export const CUSTOM_FEATURES: FeatureChoice = {
    on: ['pwa'],
};

  2. Name it in src/custom/pwa.ts. Anything you leave out keeps Arc CMS's default; every key and default is in Installable app (PWA):

    export const CUSTOM_PWA: Partial<PwaConfig> = {
    name: 'Sanskrit for Kids',      // install dialog and app switcher
    shortName: 'Sanskrit',          // under the home screen icon, about 12 characters
    themeColor: '#e8590c',          // browser bar and phone status bar
    startUrl: '/learn',             // the page the home screen icon opens
};

  3. Add one icon: a square image of at least 512 by 512 pixels, saved as src/custom/pwa-icon.svg or src/custom/pwa-icon.png. Keep the important part inside the middle 80%, since Android crops it into a circle or rounded square.

  4. Build and deploy the website. These settings are read at build time, so every change needs a new build and a hosting deploy. See Deploy.

Putting enabled in src/custom/pwa.ts stops the build with a message. The switch lives only in src/custom/features.ts.

What the build makes

FileFrom
The web app manifestYour name, short name, description, colors and start page, shown full screen (standalone) with the whole site as its scope
Every icon sizeYour one image: the standard app icon sizes, the maskable icon, and the 180 by 180 pixel iPhone icon
The service worker, sw.jsStores the app's main code, styles and fonts; pages always come from the network first, and the stored app opens when there is no connection
iPhone tagsThe home screen icon link and the short name as the iPhone app title

With the feature off, none of these are built, and a visitor who still has an old service worker gets it removed on their next visit.

Show the install button

Arc CMS shows the install card at the top of the member dashboard. To show it on a page of your own, such as your app's start page, add <arc-install-prompt /> (see Installable app (PWA)). It shows what fits the browser, and nothing once the app is installed.

On your published home page, give any button data-arc-install hidden: it appears when the browser offers installing and asks on a click (see Build your home page).

Test that it installs

  1. On your computer: build, serve the build, and check Chrome's DevTools, Application, as described in Installable app (PWA). npm run dev has no service worker, so it cannot be used for this.

  2. On an Android phone: deploy to your Firebase Hosting site, open it in Chrome, and install from the install card or the browser menu. The icon, name and splash colors come from your settings.

  3. On an iPhone: open the same address in Safari and add it to the home screen (below).

  4. After a change: build and deploy again, then reopen the installed app. It offers the new version with an Update button instead of reloading by itself.

Show the update yourself

By default Arc CMS shows its own "A new version is ready" bar, and holds it back on full-screen pages until a normal page opens. An app that lives entirely on full-screen pages (a kiosk, a till) would never see it. Such an app shows the update where it suits, such as a lock screen, and Arc CMS stays out of the way.

  1. Tell Arc CMS the page owns the update. Add pwaUpdate: 'app' to the route's data. Every page below that route inherits it, and Arc CMS's own bar is not shown there at all. 'app' is the only value; any other is ignored.

    { path: 'lock', loadComponent: () => import('./lock.component').then((m) => m.default),
  data: { fullScreen: true, pwaUpdate: 'app' } }

  2. Use PwaService (src/app/core/pwa/pwa.service.ts) in that page:

    MemberWhat it does
    updateReady()A read-only signal, true while a new version is waiting. Always false when the pwa feature is off.
    checkForUpdate()Looks for a new version now, instead of waiting for the hourly check. It resolves once the browser has looked, and does nothing when the feature is off, offline, or before the service worker has registered.
    applyUpdate()Switches to the waiting version and reloads the page. It does nothing when no update is waiting.
     
import { Component, inject } from '@angular/core';
import { PwaService } from '../app/core/pwa/pwa.service'; // from src/custom/lock.component.ts

@Component({
    selector: 'app-lock',
    template: `
        @if (pwa.updateReady()) {
            <button type="button" (click)="pwa.applyUpdate()">Update now</button>
        }
    `,
})
export default class LockComponent {
    readonly pwa = inject(PwaService);

    constructor() {
        void this.pwa.checkForUpdate(); // the lock screen is a quiet moment to look
    }
}

Arc CMS never calls applyUpdate() itself, on any page, so a page is never reloaded in the middle of a task. Call it only when the person is at a safe point. On a page without the flag, nothing changes: the bar shows as before.

Do not leave an update waiting for long. A deploy replaces the old version's code files on the server, so a page of the old version that has not opened a route yet cannot load that route until the update is applied (in a test it failed with "Failed to fetch dynamically imported module"). Offer the update at the next quiet moment, such as the lock screen.

iPhone and iPad

  • Only Safari can install. The install card shows the two steps (tap Share, then "Add to Home Screen"); in another browser it asks the person to open the page in Safari, with a Copy link button.
  • iPhone reports no install event, so the install numbers count the first opening from the home screen as the install.
  • The home screen uses the iPhone icon and the short name, both made from your settings.

Wrap it for the app stores

To publish in the App Store or Google Play, wrap the installable app with Capacitor: add Capacitor to the project, point its web directory at the browser files that npm run build writes, add the plugins your app needs (push notifications, camera and so on, chosen per app), and build the iOS and Android apps with Xcode and Android Studio. Follow Capacitor's own documentation for each step.
