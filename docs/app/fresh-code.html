Ask for a fresh code

A few actions are worth more than a PIN, which may have been seen over someone's shoulder: changing payment keys, a full export, deleting a business, setting up a device. Before one of them, ask the signed-in person for a fresh code. Arc CMS sends it to their own email address or phone number, and your function goes ahead only with the proof that confirming it gives. It works for every account, including those that sign in with a PIN and so have no password to type again.

In your page

FreshCodeService.confirm() opens Arc CMS's own dialog. It sends the code as it opens, says where it went, takes the 6 digits and resolves with the proof, or null when the person cancels:

import { FreshCodeService } from '../../app/core/sign-in/fresh-code.service';

private readonly freshCode = inject(FreshCodeService);

async setUpTill(): Promise<void> {
  const proof = await this.freshCode.confirm({ purpose: 'pos-setup' });
  if (!proof) return; // cancelled
  await arcCallable(this.functions, 'custom-setUpTill')({ proof, name: 'Till 2' });
}

The purpose names the action: lower case letters, digits, - and _, starting with a letter. The proof is for that purpose only.

To ask inside a sheet of your own instead, call the two steps yourself and use the same code boxes as the sign-in page, arc-code-input (src/shared/components/code-input/):

const sent = await this.freshCode.request('pos-setup');       // { via, to, wait, testCode? }
// ... show "We've sent a 6-digit code to " + sent.to, and <arc-code-input (completed)="..."> ...
const proof = await this.freshCode.confirmCode('pos-setup', code);

A refusal comes as an error whose message is already in the member's language, with details.reason (code-wrong, code-expired, code-tries, wait, too-many-codes, no-contact).

In your function

Use the proof up with useFreshCodeProof() from the app kit before doing anything else:

// functions/src/custom/tills.ts
import { onCall } from 'firebase-functions/v2/https';
import { useFreshCodeProof } from '../app-kit/index.js';

export const setUpTill = onCall(async (request) => {
  await useFreshCodeProof(request, request.data?.proof, 'pos-setup');
  // ... the action ...
});

It throws permission-denied with details.reason fresh-code-required when the proof is missing, already used, more than 5 minutes old, another person's or for another purpose. Your page then asks for a code again.

How it works

  • Where the code goes. The person's verified email address, which costs nothing to send to; with none, their verified phone number by SMS; with neither, an email address on the account that is not verified yet. The person never types an address, and nobody can name another. An account with neither (an app account) is refused with no-contact.
  • The code is a sign-in code: 6 digits, good for 10 minutes, 5 tries, one a minute (asking again sooner sends nothing new), 5 an hour per person and 20 an hour per caller's address. The email uses the "Your verification code" template.
  • The proof is a random value only its hash is kept of, in auth_fresh_proofs, which no browser can read. It works once, for that person and purpose, within 5 minutes of confirming the code. A new confirmation for the same purpose replaces it. Deleting the account deletes any left unused.
  • Who may ask. Only a signed-in person, for themselves. A blocked account is refused, and so is a locked app account.
  • While testing with the Simulated email provider or the Test SMS provider, nothing is sent and the code is in Email Logs or SMS Logs. It shows in the dialog only when an admin turned on showing reset codes on screen, as for Forgot PIN, since a fresh code guards what a session alone may not do.

Add setUpTill to functions/src/custom/public-callables.txt, as every callable of yours (see Write your own Cloud Functions).
