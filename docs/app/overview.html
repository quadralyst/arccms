The one rule: never edit core

Every file Arc CMS ships is core. Your app's code goes only in the custom space: src/custom/, functions/src/custom/, your own rules and index files, custom/ at the root for scripts and data, and your CI workflows in .github/ (Use the custom space). Arc CMS ships those files once, empty, and never changes them again, so pulling an update never conflicts with your work.

If your app needs something core does not offer, it becomes a general feature or a new plug point in Arc CMS, and your app pulls it. Before every commit, run:

npm run check:core

It lists every core file you changed and fails when there is one. See Core and custom for the reasoning.

The steps, in order

Start with a working copy: Install, Configure a project and Create the first admin. Then:

  1. Use the custom space: learn which file does what.

  2. Choose your app's features: turn off what the app does not need.

  3. Add pages and routes: the app's own screens.

  4. Add admin menu items: links to your admin screens.

  5. Build the member area: where signed-in people land and what they see.

  6. Write your own Cloud Functions: callables and triggers.

  7. Set security rules and indexes: protect the app's data.

  8. Follow the account contract: where each person's data lives.

  9. Set up sign-in: choose how people sign in.

  10. Add payments and premium features: charge for the app.

  11. Make it installable: name, colors and icon.

  12. Connect your app's users: email the app's users from Arc CMS.

  13. Share a Firebase project: only when Arc CMS lives next to another app.

  14. Keep core untouched: check your work and pull Arc CMS updates.
