Use the custom space

All of your app's code goes in a handful of files and folders that Arc CMS ships once, empty, and never changes again. This page lists each one, what it is for, and where Arc CMS reads it.

Styles and translations

Put global styles in src/custom/styles.css. Styles for one page belong in that page's component. Styles for the public website (header, footer, templates) go in src/custom/site/site.css, and the words of the website's templates in src/custom/site/strings/ (see Publish in more than one language).

Add the app's words to src/custom/i18n/en.json under a custom key, and the same keys to every other language file. A key that already exists in core is reworded for the whole admin:

{
  "custom": { "nav": { "lessons": "Lessons" } },
  "admin": { "nav": { "users": "Parents" } }
}

The admin has two languages, English and Hindi, and each reads its own file in src/custom/i18n/. See Languages.

Use core building blocks

The rule forbids editing core files, not using them. Your pages import core components the same way core pages do and get every later fix for free. These are meant for apps:

ComponentImport fromFor
arc-page-headersrc/shared/components/page-header/page-header.component.tsThe title row of every admin and member page
app-global-tablesrc/shared/components/global-table/global-table.component.tsAny list: columns, sorting, empty and loading states, row actions (see its src/shared/components/global-table/README.md)
arc-row-actionssrc/shared/components/row-actions/row-actions.component.tsThe actions of a row in a table or card you build yourself
app-user-shellsrc/app/pages/user/user-shell.component.tsThe member area's layout and menu
PwaServicesrc/app/core/pwa/pwa.service.tsWhether a new version of the installable app is waiting (updateReady()), looking for one now (checkForUpdate()) and switching to it (applyUpdate()), for an app that shows the update itself (Make it installable)

If a building block falls short, the missing option is added to it in Arc CMS. Copying the component into the custom space loses every later fix.

Why updates never conflict

  • Arc CMS ships each file in src/custom/ and functions/src/custom/ once, empty, and never changes it again, so a merge never touches your version.
  • The app's rules, indexes, rules tests and docs are files Arc CMS does not ship at all.
  • Everything built from your choices (the combined rules in .arc-build/ and the functions' feature files) is generated and ignored by git.

npm run check:core sorts every file you changed into the custom space (fine), install settings such as src/environments/environment.ts and src/environments/arc-install.ts (fine), dependency lists such as package.json (fine, worth a look), and core (a problem). See Keep core untouched.

Moving a core file into the custom space to change it still counts as a core change: npm run check:core still lists the core file's old path. If you need to change what a core file does, ask for a plug point or a setting in Arc CMS instead.
