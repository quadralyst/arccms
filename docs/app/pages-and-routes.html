Add pages and routes

Each page of your app is an Angular component with a route in src/custom/routes.ts. Give every page an explicit route there, and protect member and admin pages with the core guards.

Add a page

  1. Create the component, such as src/custom/learn/learn.component.ts, with a default export:

    import { Component } from '@angular/core';

@Component({
  standalone: true,
  template: `<h1>Learn</h1>`,
})
export default class LearnComponent {}

  2. Add its route to CUSTOM_ROUTES in src/custom/routes.ts:

    import type { Routes } from '@angular/router';

export const CUSTOM_ROUTES: Routes = [
  { path: 'learn', loadComponent: () => import('./learn/learn.component').then((m) => m.default) },
];

  3. Start the app with npm run dev and open /learn.

The shape of a route

CUSTOM_ROUTES is a plain Angular Routes list. The fields you use most:

FieldFor
pathThe address without the leading slash, such as 'learn' or 'learn/:lessonId'
loadComponentThe page, loaded only when someone opens it
titleThe browser tab title
canActivateGuards that decide who may open the page (below)
dataValues a guard reads, such as allowedRoles
childrenPages shown inside a layout, such as the admin shell

Core adds your routes after its own explicit routes, such as pricing and account, so those always win over yours and an app page cannot replace them by accident. Pick addresses no core page uses.

Who may open a page

Always give roleGuard a data.allowedRoles list. Without one, the guard lets every visitor open the page and only shows a warning.

A member page:

import { userGuard } from '../app/pages/user/user.guards';

export const CUSTOM_ROUTES: Routes = [
  {
    path: 'learn',
    canActivate: [userGuard],
    loadComponent: () => import('./learn/learn.component').then((m) => m.default),
  },
];

To keep the member menu around a member page, see Build the member area.

A guard only decides what the browser shows. The data a page reads is protected by security rules (Set security rules and indexes).

Add an admin page

An admin page needs the admin shell (the side menu and layout) and the admin guard. Give it the same route shape core uses for its own admin pages:

  1. Create the component, such as src/custom/admin/lessons.component.ts:

    import { Component } from '@angular/core';
import { TranslocoPipe } from '@jsverse/transloco';
import { PageHeaderComponent } from '../../shared/components/page-header/page-header.component';

@Component({
  standalone: true,
  imports: [PageHeaderComponent, TranslocoPipe],
  template: `<arc-page-header [title]="'custom.lessons.title' | transloco"></arc-page-header>`,
})
export default class LessonsComponent {}

  2. Add the route, with the admin shell as the parent and your page as its child:

    import type { Routes } from '@angular/router';
import { roleGuard } from '../app/guards/role.guard';

export const CUSTOM_ROUTES: Routes = [
  {
    path: 'admin/lessons',
    loadComponent: () => import('../app/pages/admin.page').then((m) => m.default),
    canActivate: [roleGuard],
    data: { allowedRoles: ['admin'] },
    children: [
      { path: '', loadComponent: () => import('./admin/lessons.component').then((m) => m.default) },
    ],
  },
];

  3. Add the title to src/custom/i18n/en.json ("custom": { "lessons": { "title": "Lessons" } }) and link the page from the admin menu (Add admin menu items).

An admin page that has only a page file and no explicit route does not reliably reach the browser's route table. The address then falls through to the public content route and shows "Content Not Found" in the public layout. Firebase Hosting answers every address with the app shell and HTTP 200, so a status check does not catch it: open the page in a browser. Give every admin page an explicit route as above.

Keep components that have an explicit route outside src/custom/pages/, as above, or name them without .page. Every .page.ts file in that folder also gets an address of its own from its file name, without the admin shell, the guards of the explicit route, or a whenOn around it.

Pages found by file name

Files in src/custom/pages/ become routes by name, like the core pages in src/app/pages/:

FileAddress
src/custom/pages/learn.page.ts/learn
src/custom/pages/learn/index.page.ts/learn
src/custom/pages/learn/[lessonId].page.ts/learn/:lessonId
A folder in parentheses, such as src/custom/pages/(learning)/Groups files and adds nothing to the address

Two folders in parentheses side by side, such as src/custom/pages/(learning)/ and src/custom/pages/(practice)/, each become an empty-path route, and after a fresh start of npm run dev only one of them survives: the other page's address falls through to a later route. Give the second page a plain folder or an explicit route, and check new page files again after restarting the dev server.

A page file sets its title and guards with a routeMeta export:

import { RouteMeta } from '@analogjs/router';
import { userGuard } from '../../app/pages/user/user.guards';

export const routeMeta: RouteMeta = {
  title: 'Learn',
  canActivate: [userGuard],
};

A page file needs no entry in src/custom/routes.ts. Your explicit routes come before the file-based pages, so when both give the same address, the explicit route is used. Explicit routes remain the recommended way, and the only one for admin pages.

Routes that belong to a feature

If a page only makes sense while a feature is on, wrap its routes so they go when the feature is off (Choose your app's features):

import { whenOn } from '../app/core/features/feature-routes';

export const CUSTOM_ROUTES: Routes = [
  ...whenOn('payments', [
    { path: 'learn/premium', loadComponent: () => import('./learn/premium.component').then((m) => m.default) },
  ]),
];
