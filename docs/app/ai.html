Use AI in your app

Your own Cloud Functions can ask a language model to read, write, translate, summarise or sort, or ask a model to make a picture, speech, a sound or a video, with askAi from the app kit. You declare each use as a purpose in functions/src/custom/ai.ts: what it makes, what it takes, the instruction, and the shape of the answer. Admins choose the providers and models, set the keys, and see what every call cost in Settings, AI. Arc CMS checks the answer against your shape, keeps a record of each call, and stops at the limits you set.

Arc CMS has no AI feature of its own: every use is your app's. It needs the ai feature, which is on unless your app turns it off (see AI for the admin side).

An example: reading a receipt

A shop photographs its supplier receipts, and the app reads each one into lines and a total for the owner to check. First the purpose, in functions/src/custom/ai.ts:

import type { AiPurposes, JsonSchema } from '../app-kit/index.js';

const RECEIPT: JsonSchema = {
  type: 'object',
  properties: {
    supplier: { type: 'string' },
    date: { type: ['string', 'null'], description: 'yyyy-mm-dd' },
    currency: { enum: ['CHF', 'EUR'] },
    lines: {
      type: 'array',
      items: {
        type: 'object',
        properties: { name: { type: 'string' }, quantity: { type: 'number' }, price: { type: 'number' } },
        required: ['name', 'quantity', 'price'],
      },
    },
    total: { type: 'number' },
  },
  required: ['supplier', 'date', 'currency', 'lines', 'total'],
};

export const AI_PURPOSES: AiPurposes = {
  'receipt-read': {
    label: 'Receipt reading',
    description: 'Reads a photographed receipt into its lines and total.',
    input: { pictures: { max: 3, maxMb: 10 }, pdfs: { max: 1, maxMb: 10 } },
    instruction: 'Read this supplier receipt. Give every line with its quantity and price, and the total as printed. Leave the date null when it cannot be read.',
    output: { schema: RECEIPT },
    tier: 'thorough',
    thinking: 'low',
    perKeyPerDay: 20,
    limitKeyLabel: 'business',
    testAnswer: { supplier: 'Test Supplier', date: '2026-10-01', currency: 'CHF', lines: [{ name: 'Flour 25 kg', quantity: 2, price: 38.5 }], total: 77 },
  },
};

Then your own callable, in your functions, reads the photo the person uploaded:

import { onCall, HttpsError } from 'firebase-functions/v2/https';
import { askAi } from '../app-kit/index.js';

export const readReceipt = onCall({ timeoutSeconds: 120, memory: '1GiB' }, async (request) => {
  const { businessId, path } = request.data;
  // Your check: the caller works for this business, and the file is theirs.
  await assertStaff(request, businessId);
  if (!path.startsWith(`app/receipts/${businessId}/`)) throw new HttpsError('permission-denied', 'Not your file.');

  const r = await askAi({
    purpose: 'receipt-read',
    input: [{ storagePath: path }, 'Prices are in Swiss francs.'],
    limitKey: businessId,
    ref: `businesses/${businessId}/receipts/${request.data.receiptId}`,
  });
  if (!r.ok) return { reason: r.reason, wait: r.wait ?? null };
  return { receipt: r.data };
});

The answer is data in your shape, or a named reason. Your page shows the lines for the owner to check before anything is saved.

Declare your purposes

AI_PURPOSES maps each purpose's id (lower case letters, digits and -, not starting with arc-) to what it is. A mistake in the file stops the functions from loading, so the deploy fails with the reason.

FieldWhat it says
label, descriptionWhat admins see in Settings, AI
inputWhat a call may send. Text is always allowed, up to text.maxChars (default 20,000 characters). pictures (JPEG, PNG, WebP) and pdfs each take { max, maxMb }: how many, and the largest, at most 15 MB. All the files of one call come to at most 15 MB: they go inline as base64, a third larger, and providers take about 20 MB in one request. A call with a kind the purpose does not take throws.
instructionThe prompt. It stays on the server: Settings, AI does not show it, except on a call kept by Keep what is sent and answered.
output'text' (the default), or { schema }: the answer is data of that shape, checked by Arc CMS
tiercheap, fast (the default) or thorough: which of the admin's model lists answers, unless the admin gives the purpose its own
perKeyPerDayHow many units one key may use a day. With it, every call needs a limitKey. The admin can change the number; a purpose without it has no allowance. Each key has its own count: pass a business id and each business gets this many.
limitKeyLabelOptional: what a limitKey is, in a word, such as 'merchant'. Settings, AI then says "Daily allowance for each merchant" and "merchant b1" on the usage and call rows. Default: "user or business".
testAnswerThe answer in test mode: the data or text itself, a function of the input, or aiTestFailure(reason). A fixed answer is checked against the schema when the functions load.
thinkingOptional, for a model that thinks before it answers: 'low' for quick reading and sorting (faster, fewer billed tokens), 'high' for hard reasoning. Sent to OpenRouter, OpenAI and Gemini; other providers ignore it. A model that thinks past maxOutputTokens gives no answer (unreadable), and its tokens are still billed.
makesOptional: 'text' (the default), 'data' (the default with a schema), or a kind that answers with files: 'image', 'speech', 'audio' (a sound or music) or 'video'. See Make files.
allowanceInOptional: what perKeyPerDay counts. 'calls' (the default: units a call), or the amount: 'pictures', 'characters' of the text sent, or 'seconds' of audio or video asked for. So "20 pictures a day" needs no counting by you.
fallbackOptional: false lets only the first model of the list answer, such as for one voice throughout. Default true.
image, speech, audio, video, saveTo, deleteAfterDays, cacheFor a purpose that makes files: its settings and where its files go. See Make files.
maxOutputTokens, temperature, timeoutSecondsOptional. timeoutSeconds (5 to 540, default 60) is for the whole call, fallbacks included. Give your own function a longer timeoutSeconds than the purpose, and memory for the files: about seven times their size, so memory: '1GiB' for photos of several MB.

The schema is the part of JSON schema models take: type (one or a list, such as ['number', 'null']), properties, required, additionalProperties: false, items, enum, minItems, maxItems. Other keywords, such as description, are passed to the model and not checked.

What askAi takes

FieldWhat it is
purposeOne of your purposes' ids
inputOne part or a list, in the order the model reads them: a string, { text }, { storagePath, mimeType? } (a file in the project's bucket) or { bytes, mimeType, name? }. Give mimeType when a path does not end in .jpg, .png, .webp or .pdf.
limitKeyWhose allowance the call uses, such as a business id: 1 to 200 characters without / or spaces
unitsHow much of the allowance it uses, such as the number of pages. Default 1.
perDayOptional: this key's own allowance today, such as from its plan. A whole number from 0, used in place of the admin's and the purpose's. Needs a limitKey. See Allowances by plan.
refYour own reference, kept on the record
saveAsA file kind with saveTo: the path for the first file, inside that folder, such as app/article-audio/a1/p3.mp3. More files get -2, -3.
image, speech, audio, videoA file kind: this call's settings over the purpose's, such as image: { count: 2 }. Settings for another kind throw.

Arc CMS reads storagePath with the functions' rights, which can read every file. It takes only paths inside the project's bucket, without .., but it cannot know which files the caller may read: check that yourself before you pass a path from a browser, as the example does.

Allowances by plan

Every key gets the purpose's perKeyPerDay, or the admin's number in its place. When your keys have plans, pass each one's number with the call; a key without one still gets the shared number. Keep perKeyPerDay on the purpose too: without it, a call that passes no number has no limit.

const plan = await planOf(businessId); // your own data
const r = await askAi({
  purpose: 'receipt-read',
  input: [{ storagePath: path }],
  limitKey: businessId,
  units: pages,
  perDay: plan.receiptPagesPerDay, // such as 5 on Free, 50 on Pro
});

The count for the day is the same whatever number is passed, so a business that moves to a larger plan at noon keeps what it used in the morning. A perDay of 0 gives that key no calls. Take the key and its plan from the signed-in account on the server, never from what the browser sends, or anyone could name another business or a larger number.

What comes back

{ ok: true, data, usage, recordId } for a purpose with a schema, { ok: true, text, usage, recordId } for text, { ok: true, files, usage, recordId } for a file kind, with cached: true when the files came from the cache. usage holds the model that answered, the tokens, the cost in USD and the time. Otherwise { ok: false, reason, usage, recordId }, with wait (seconds) when trying later can help and detail for your logs:

ReasonWhat happenedWhat to show
unreadableNo usable answer: the file was missing or not what it said, or the answer did not fit the schema"This could not be read. Try another photo."
blockedThe provider's safety rules blocked the question or the answer"This could not be read." Do not retry the same input.
too-largeMore text, files or MB than the purpose takes, or more than the model reads"Too large: use fewer or smaller pictures."
limitscope: 'key': the key used its allowance today. scope: 'budget': the month's budget is spent."You have read 20 pages today. More tomorrow." with wait
unavailableEvery model in the list was busy, down, gone or refused its key"Busy right now. Try again in a minute."
timeoutNo answer within the purpose's time"That took too long. Try again."
offThe ai feature is off, the admin switched the purpose off, or no model is set up for itHide the button, or say the feature is not available

A developer's mistake throws instead: an unknown purpose, a kind of file the purpose does not take, a missing limitKey for a purpose with an allowance, or a wrong type. A call that fails before a provider answers gives its units back. One the provider answered, even with a block or an answer that did not fit, was paid for, so its units count; so does one that timed out, since the provider most likely finished and billed it.

Make files

A purpose with makes: 'image', 'speech', 'audio' or 'video' answers with files, which Arc CMS saves to Storage and never hands back as bytes. Its instruction is optional: for a file kind it is a house style, added after the text the call sends.

export const AI_PURPOSES: AiPurposes = {
  'article-audio': {
    label: 'Article audio',
    makes: 'speech',
    input: { text: { maxChars: 2000 } },
    voices: { narrator: { elevenlabs: 'ELEVENLABS_VOICE_ID', sarvam: 'priya', vertex: 'en-US-Chirp3-HD-Kore' } },
    speech: { language: 'en-US', format: 'mp3' },
    saveTo: 'app/article-audio',
    cache: true,
    perKeyPerDay: 50_000,
    allowanceIn: 'characters',
  },
};

const r = await askAi({
  purpose: 'article-audio',
  input: paragraph.text,
  voice: 'narrator',
  saveAs: `app/article-audio/${articleId}/${paragraph.id}.mp3`,
  limitKey: siteId,
});
if (r.ok) save(r.files![0].path); // { path, mimeType, bytes, seconds }
FieldWhat it says
imageaspect (1:1, 4:3, 3:4, 3:2, 2:3, 16:9, 9:16, 21:9), resolution (standard about 1 MP, high about 4 MP), quality (low, medium, high), count 1 to 4, seed, negativePrompt, format. Each model takes what it can; the rest is not sent.
speechlanguage (such as en-US), speed 0.5 to 2, format (mp3, wav, opus), style for a model that takes an instruction
audioseconds 0.5 to 600, loop, format
videoseconds, aspect, resolution (480p to 4k), sound, seed, negativePrompt
saveToThe folder your files go in, such as app/article-audio, served by your own rules in storage.app.rules. Not one of Arc CMS's folders (ai-files, ai-calls, users, email-logs, mediaFiles, mediaImages). Without it, files go to Arc CMS's private ai-files/{purpose}/{month}/, which only admins read.
deleteAfterDaysFiles left in ai-files/ are deleted this many days after they were made. Without it they stay until you move or delete them. Arc CMS never deletes a file in your saveTo folder.
cachetrue (365 days) or { days }: the same text, settings and input files on the same model give the same file, with no new call. A hit counts against nothing: no budget, no allowance, no call in Usage. It still leaves a record marked cached. The cache keeps its own copy of each file in ai-files/_cache/ and copies it to where each call wants it, so moving or deleting your file never takes it from the next call. The admin can switch the cache off.

Move a file to where you keep it with moveAiFile(from, to) from the app kit: it moves the file and points the call's record at the new place. It moves only a file a call made, never onto a file that is already there, and never into Arc CMS's own folders. In test mode each call gets a small stand-in instead: a grey picture of the asked size, a second of silence for every 15 characters of speech (at most 10), the asked length of silence for audio, a 2-second grey video. Stand-ins always go to ai-files/_test/, never to your folder, and are deleted after a day.

Speech is the first file kind with providers. Pictures, video and other audio are ready in the same way (their files, the cache and test mode), so you can build and test their screens now, but a live call for one of them answers off until its providers arrive.

Speech and voices

A speech purpose names its voices, and a call asks for one by name, never by a provider's voice id, so your code stays the same whichever provider answers:

voices: {
  narrator: { elevenlabs: 'ELEVENLABS_VOICE_ID', sarvam: 'priya', vertex: 'en-US-Chirp3-HD-Kore' },
  guest: { elevenlabs: 'ANOTHER_VOICE_ID' },
},
  • Each voice maps a provider to its voice id. The keys are elevenlabs, sarvam, minimax and vertex (Google Cloud Text-to-Speech). The first voice is the default; a call passes voice: 'guest' for another.
  • The admin can change every mapping in Settings, AI, Purposes, choosing from each provider's voice list and playing a sample. Their choice wins over yours. A purpose with no voices gets one voice, default, for the admin to map.
  • A model whose provider has no id for the asked voice is skipped, so a list of several providers keeps the same voice only where each has one. Set fallback: false to have only the first model ever speak.
  • The instruction is never read aloud: speech says the call's text only.
  • Long text is not split. Each model takes so much a request (Sarvam AI 2,500 characters, MiniMax under 10,000, ElevenLabs 5,000 to 40,000 by model, Google 5,000 bytes, which is about 1,600 characters of Devanagari). A longer text skips that model, and the call answers too-large when no model in the list takes it. Send a paragraph at a time.
  • A model is also skipped for a format it does not make (Sarvam AI and some others make no Opus) or a language it does not speak (Sarvam AI speaks 11 Indian languages, Indian English among them). Give speech a language: without one, Sarvam AI reads the text as Indian English, whatever its script.
  • A Google voice speaks only with the model of its type (en-US-Chirp3-HD-Kore with tts-chirp3-hd), since Google prices by type; a voice of another type skips the model.
  • Speech bills by the characters sent: Arc CMS uses the provider's own count when it gives one (ElevenLabs and MiniMax do), else counts the characters itself. The file's seconds comes from the provider or is read from the file. The record keeps the voice's name and the id that spoke, and the cache keys on the voice, so the same words in another voice are another file.

Which model answers

Each tier, and any purpose the admin gives its own list, is a list of up to 5 models. The first answers. The next tries only when the one before is busy or down, refuses its key, has gone (a model Google or another provider retired), or used up its share of the time. Never after a safety block, an input that is too large or an answer that does not fit: another model would not do better. A model that cannot read what you send, such as a picture to a text-only model, is skipped. Because every answer is checked, a cheap model that promises only JSON is safe to use: it gets your schema in its instruction, and an answer of the wrong shape comes back as unreadable.

A file kind has one list for its kind (Picture models, Speech models, Audio models, Video models in Settings, AI) instead of a tier, and offers only models that make that kind. With fallback: false only the first model answers. A provider that says "too many requests" with a short wait gets one more try on the same model; a connection with a limit set in Settings, AI waits for a place rather than failing (see Costs, limits and records).

Providers Arc CMS offers: Alibaba Cloud Model Studio in Frankfurt (EU), OpenRouter, Hugging Face, OpenAI, OpenAI's EU projects, DeepSeek, Anthropic, the Google Gemini API with a key, Mistral (and its EU address), Groq, xAI, Sarvam AI (text and speech), any other address that speaks the OpenAI Chat Completions format, and Google Cloud (Vertex AI) for Gemini and for speech. For speech only: ElevenLabs and MiniMax. Where each processes data is on its card in Settings, AI: choose with your client.

Not tested live yet: Anthropic, the Gemini API, Mistral, Mistral EU, Groq, xAI and Sarvam AI's chat, and all speech (ElevenLabs, Sarvam AI, MiniMax and Google Cloud Text-to-Speech), were built from each provider's documentation as read on 2 November 2026 and tested against a fake server, never with a real call. Settings, AI marks them "Not tested live yet". The first project that uses one runs it for real, fixes what differs, and confirms its prices. Among what the docs left open: whether ElevenLabs' character-cost header counts characters or credits (Flash bills half a credit a character, so credits would count it at half its cost), which HTTP status ElevenLabs gives when the characters run out, whether Sarvam AI says 402 or 429 for no credit, and whether MiniMax also gives an HTTP error status on a failure. Arc CMS reads each provider's own error code, so both readings work.

Gemini on Vertex AI

A Vertex provider needs no key: it calls Gemini in your own Google Cloud project with the functions' service account. Set it up once:

  1. In Google Cloud, switch on the Vertex AI API for the project.

  2. Give the functions' service account (by default PROJECT_NUMBER-compute@developer.gserviceaccount.com) the Vertex AI User role.

  3. Add the provider in Settings, AI. Its location starts at the multi-region of your functions region (eu for a europe-* region, us for us-*), never global unless you type it.

Google's data residency guarantees name the eu multi-region and some single regions, such as Frankfurt (europe-west3) and the Netherlands (europe-west4); the eu multi-region covers EU member states only, not Switzerland or the United Kingdom. Zurich (europe-west6) serves Vertex AI but is not among the guaranteed regions. The global location may process anywhere in the world. Check Google's current table for your model before you promise a client where their data stays.

Test it

A new install is in test mode: no provider is called and nothing is spent. Each call gets its purpose's testAnswer, or an answer built from the schema (empty texts, zeros, empty lists), or "Test answer for" and the label, and is still recorded and counted against the allowance, so you can see your limit screen. To see your screen for a failure, return one from the test answer:

import { aiTestFailure } from '../app-kit/index.js';

testAnswer: (input) => (input.files.length > 2 ? aiTestFailure('too-large') : SAMPLE_RECEIPT),

In your unit tests, captureAiAsks() records each call instead of touching Firestore, Storage or a provider, after checking the input exactly as for real. Storage files are recorded by path, not read:

import { captureAiAsks } from '../../app-kit/index.js';

const ai = captureAiAsks({ answers: { 'receipt-read': SAMPLE_RECEIPT } });
try {
  const result = await readReceipt(callAs(staff, { businessId: 'b1', path: 'app/receipts/b1/r1.jpg' }));
  expect(ai.asks[0]).toMatchObject({ purpose: 'receipt-read', limitKey: 'b1' });
  expect(result.receipt.total).toBe(77);
} finally {
  ai.stop();
}

To try a real model, an admin sets a key and clicks Test on the provider: one tiny live call, even in test mode, that costs a fraction of a cent and is recorded as purpose arc-connection-test. Switch the mode to Live when the app is ready.

Costs, limits and records

  • Every call is recorded in AiCalls for 60 days: the purpose, each model tried and how it went, the tokens in and out (thinking included in out), the cost in USD, the time, your ref and limitKey. Not what was sent or answered, unless the admin switches on Keep what is sent and answered for the purpose: then the text and the answer are on the record and each file is copied beside it in Storage, for 60 days. Turn it on while testing; it may hold personal data.
  • The cost is the provider's own figure when it reports one (OpenRouter does), else the amount times the price in Settings, AI, by what the model bills: tokens (input, output, and the cheaper cached input and dearer cache writes apart, with a higher price above a prompt size where the provider has one), pictures, characters (per 1,000) or seconds. A provider that prices in another currency (Sarvam AI, in rupees) counts 0 until the admin sets its rate in USD. Arc CMS ships the prices it has checked; a model without a price is counted as free until the admin sets one. It is an estimate: the provider's invoice is the true figure.
  • The month's totals by day, purpose, model and key are kept 24 months. aiUsage({ limitKey, purpose?, month? }) gives one key's totals, for example to show a business its use or pass the cost on.
  • The monthly budget (20 USD on a new install) stops live calls when it is spent, with limit and scope: 'budget'; a budget of 0 stops every live call. It is checked before each call, so calls running at the same moment can pass it by about one call's cost each. A model with no price is counted as 0 USD, so the budget cannot stop it: Settings, AI warns about each one until a price is set. A timed-out call is recorded with no tokens, though the provider may have billed it. Admins get a notification and an email at 80% and at 100%.
  • A day for the allowance and the totals is the site's day, in the time zone of Settings, Localization.
  • Pacing: a connection can have at most so many requests a minute and so many at once, across every instance (Sarvam AI and MiniMax start at 60 a minute, ElevenLabs at 3 at once, their entry plans' limits; the admin sets the plan's numbers, or 0 for none). A call over a limit waits for a place while its time allows, then answers unavailable with wait.
  • Deleting an account does not delete the records of its calls: they go after 60 days, and the month's totals per key, which hold the limitKey, after 24 months. Use an id, such as a business id, as limitKey and ref, never a name or an email address.
  • What Arc CMS adds to your Google Cloud bill is small next to the model's: about three Firestore reads and three to four writes for each live call, one daily cleanup job, and Storage for files kept with a purpose's content.

Deploy

  1. Check that src/custom/features.ts does not turn the feature off (off: ['ai']). It is on by default.

  2. Deploy the functions and the rules (npm run deploy). The feature's own functions (setAiKey, removeAiKey, testAiConnection, aiSetupInfo, cleanUpAi, readAiFile, refreshAiBalance, aiVoices, aiVoiceSample) deploy with it; askAi runs inside your functions.

  3. Deploy the website, so admins get Settings, AI.

  4. In Settings, AI, add a provider, save, set its key, test it, put its model in a tier, and switch to Live.
