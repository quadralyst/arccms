Brand the sign-in page

The sign-in page at /signup, where visitors sign in or create an account, shows your site's name, logo, words and colours. Three things set them, and none of them is a core file.

Name and logo

The page takes them from Settings, About: the site name and the logo URL you already fill in for search engines. Where About has none, an app's own default fills in (src/custom/brand.ts and src/custom/logo.svg, see Brand the admin). With a name and no logo it shows the name; with neither, it shows Arc CMS's. The first step shows the logo above the card, the steps after it the name; a site can hide the logo and show the name, restyled, on every step (see the whole look). The browser tab reads "Sign in | your site name", and "Sign in" alone until the name is in.

The brand panel

On screens 992 pixels wide and more, a coloured panel sits beside the form; narrower, the form is alone and centred. Arc CMS's says only "Welcome" and "Sign in, or create your account, to continue" (public/_site/sign-in.html). Write your own as src/custom/site/sign-in.html, an HTML fragment like the header:

<div class="auth-left-content">
    <h1 class="auth-left-title" data-arc-t="sign_in_title">Sanskrit for the whole family</h1>
    <p class="auth-left-description" data-arc-t="sign_in_body">Short daily lessons your child will look forward to.</p>
</div>

Keep the auth-left-content, auth-left-title and auth-left-description classes for Arc CMS's layout, or use your own classes and style them in src/custom/site/site.css. Translate the text with data-arc-t keys in src/custom/site/strings/{lang}.json (see Publish in more than one language). When your app declares member languages, the panel follows the language chosen in the sign-in page's picker instead of the site's, from the same files (see Member languages).

An image instead

An app can fill the whole panel with an image instead: put it at src/custom/sign-in-image.webp (or .jpg, .jpeg, .png, .svg). It covers the panel, cropped to fill it and centred, and the panel's text is not shown, so put any words in the image. Pick one that still reads when its edges are cropped: the panel is half the screen wide and the full height. The file is found when the app is built, so a new image needs a deploy.

Colours, font and the whole look

The page loads src/custom/site/site.css, your website's stylesheet. Its look comes from the variables below: set the ones you want in that file and leave out the rest. Each one you leave out keeps Arc CMS's own look, so a site that sets none sees no change. Every step of the page reads them, from the first one (phone number or email) through the password, PIN and code steps to creating an account, and the code boxes and the language picker too. You never need Arc CMS's class names, which can change.

Colours and the font only:

:root {
    --arc-sign-in-panel-background: linear-gradient(135deg, #e8590c, #f59f00);
    --arc-sign-in-panel-color: #fff;
    --arc-sign-in-button-background: #e8590c;
    --arc-sign-in-button-hover-background: #d9480f;
    --arc-sign-in-accent: #e8590c;
    --arc-sign-in-font: 'Mukta', sans-serif;
}

The page and the brand

VariableSets
--arc-sign-in-page-backgroundThe page behind the card, any CSS background
--arc-sign-in-text-colorThe page's text where nothing below sets its own, such as the address a code was sent to
--arc-sign-in-fontThe page's font; load a web font in site.css with @import
--arc-sign-in-panelnone switches the brand panel off on wide screens: the card then sits alone in the middle, as on a phone
--arc-sign-in-panel-backgroundThe brand panel's background, any CSS background
--arc-sign-in-panel-colorThe brand panel's text colour
--arc-sign-in-logonone hides the logo tile; the site's name (Settings, About) then shows above the card on every step, as one line
--arc-sign-in-logo-heightThe room kept above the card for the logo, 60 pixels; 0 lets the name sit just above the card once the tile is hidden
--arc-sign-in-name-sizeThe name's size, such as 13px
--arc-sign-in-name-weightIts weight, such as 700
--arc-sign-in-name-letter-spacingThe room between its letters, such as .1em
--arc-sign-in-name-transformuppercase for small capitals
--arc-sign-in-name-colorIts colour
--arc-sign-in-name-alignleft or right lines the name up with the card's words, on a phone and on a wide screen; center by default

The name is the one in Settings, About, so the stylesheet never names the site and one app can serve many sites. It is never shown twice: with the tile hidden there is one line on every step.

The card and its words

VariableSets
--arc-sign-in-card-backgroundThe card's background colour
--arc-sign-in-card-radiusThe card's corners
--arc-sign-in-card-shadowThe card's shadow, any CSS box shadow, or none
--arc-sign-in-card-max-widthThe widest the card gets
--arc-sign-in-gutterThe room either side of the card, and of the brand above it, on a phone
--arc-sign-in-title-colorEach step's title, such as "Welcome" and "Verify Email"
--arc-sign-in-title-alignWhere the title and the lines under it sit: left, center or right
--arc-sign-in-muted-colorThe quieter words: the lines under the title, hints, the legal notice and the footer
--arc-sign-in-label-colorThe labels over fields
--arc-sign-in-link-colorThe links: change the email or number, forgot password or PIN, show PIN, resend the code

Fields

These reach every field, the boxes for a code or a PIN and the phone country beside a number included.

VariableSets
--arc-sign-in-field-backgroundThe field's background, also while it is typed in
--arc-sign-in-field-borderThe field's border, written in full: 1.5px solid #b6ac90
--arc-sign-in-field-focus-borderThe border colour of the field being typed in; without it, --arc-sign-in-accent
--arc-sign-in-accentThe border of the field being typed in, when --arc-sign-in-field-focus-border is not set, and the spinner while a signed-in account opens
--arc-sign-in-field-focus-shadowThe glow round the field being typed in, any CSS box shadow, or none
--arc-sign-in-field-shadowThe field's shadow while it is not typed in, or none
--arc-sign-in-field-radiusThe field's corners. With it set, every field is rounded all round, and so is the show-password button beside a password field. Without it, the field and that button are rounded 8px, with a small gap between them, on every screen size and in a right-to-left language
--arc-sign-in-field-heightThe field's height, the code boxes' too
--arc-sign-in-field-colorThe colour of what is typed
--arc-sign-in-field-iconsnone hides the boxed icons in front of fields (a lock, a person); the field then starts at the edge

Buttons and the language picker

VariableSets
--arc-sign-in-button-background, --arc-sign-in-button-hover-backgroundThe main button, and the button under the pointer or pressed, any CSS background
--arc-sign-in-button-colorThe main button's words
--arc-sign-in-button-radiusThe main button's corners
--arc-sign-in-button-heightThe main button's height
--arc-sign-in-button-shadowThe main button's shadow, or none
--arc-sign-in-secondary-backgroundThe button that shows a password, beside or inside its field
--arc-sign-in-secondary-colorIts icon's colour
--arc-sign-in-secondary-borderIts border colour; transparent for none
--arc-sign-in-language-backgroundThe language picker at the top, when the app has member languages (see Member languages)
--arc-sign-in-language-borderIts border colour
--arc-sign-in-language-colorIts words and globe

To see each step while you work, run npm run dev, open /signup and, in the browser's console, type ng.getComponent(document.querySelector('arc-signup')).currentStep.set('verify') with any step: request, login, pin, verify, signup, newPin, newPassword or disabled.

Your website's stylesheets are on only while a page of the website or the sign-in page is shown. The admin area and the member area never get them, so a rule in site.css cannot change how they look.
