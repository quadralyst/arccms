Turn an HTML site into an Arc CMS site

This page converts a finished HTML site, step by step: a home page, a blog list and a blog post. At the end the home page shows the latest posts and a signup form, the blog is a content type with its own fields that editors fill in the admin, and the site works in a second language. Every file is in docs/examples/blog/, before and after.

Before you start

  • An install that runs with npm run dev, and an admin account (see Run it locally).
  • A first deploy done (see Deploy for the first time). Publishing reads templates from the live site, so the website has to be deployed before posts can publish.
  • The ideas on Build a website: your site lives in src/custom/site/, and it replaces Arc CMS's own files only where you have one.

What you start with

The example site, Slow Kitchen, is in docs/examples/blog/original/:

FileWhat it is
docs/examples/blog/original/index.htmlThe home page: a hero, a signup form and three post cards written by hand
docs/examples/blog/original/blog.htmlThe blog list: every post as a card
docs/examples/blog/original/post.htmlOne post: a cover image, the title, date, author, reading time, the body and a "Read next" list

Each page repeats the same navigation and footer, and the cards and post are written by hand. After the conversion they are filled from content an editor writes in the admin.

1. Sort the pieces

Decide where each part of the old site goes. This is the whole plan:

The home page is a whole document, with its own <head>. Templates are fragments: no <html>, <head> or <body>. Arc CMS writes the page around them, with the title, description and search tags of each post. The folder name, blog, matches the content type's slug, so the admin picks it for you.

2. Header, footer and shared styles

Cut the navigation and the footer out of the old pages into their own files. Links start with / (the home page is /, the blog is /blog), not index.html. data-arc-t marks text a second language will translate, and <arc-language-switcher> becomes links to the page's other languages (it disappears while the site has one).

<!-- The site header on every page: home, blog list, posts, static pages.
     Root-relative links (/ and /blog) point at the page's language on
     translated pages. -->
<nav class="site-nav">
    <a class="logo" href="/">Slow Kitchen</a>
    <ul>
        <li><a href="/" data-arc-t="nav_home">Home</a></li>
        <li><a href="/blog" data-arc-t="nav_blog">Blog</a></li>
    </ul>
    <arc-language-switcher></arc-language-switcher>
</nav>
<footer class="site-footer" data-arc-t="footer_note">Slow Kitchen. Cooked and written at home.</footer>

3. The home page

Copy docs/examples/blog/original/index.html to src/custom/site/home.html and change four things:

  1. The navigation and footer become <arc-header></arc-header> and <arc-footer></arc-footer>.
  2. The three hand-written cards become one element, <arc-content-partials content-type="blog" count="3" section-title="Latest from the blog">. It shows the newest three posts, drawn by partials.html (step 6).
  3. The signup form gets data-waitlist-form and data-waitlist-id="newsletter". Arc CMS sends each sign-up to the form named newsletter, asks for the emailed code, and adds the terms notice above the button. If no form with that id exists, it is created the first time the page runs, so check the spelling, or create it first under Signup Forms with the slug newsletter.
  4. Styles and the script move to src/custom/site/assets/ and are linked as /site/home.css and /site/main.js. Arc CMS adds each file's version to the link, so a change reaches returning visitors.
<!doctype html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title data-arc-t="home_title">Slow Kitchen: simple seasonal cooking</title>
    <meta name="description" content="Recipes and notes on cooking with what is in season.">
    <link rel="stylesheet" href="/site/home.css">
</head>
<body>
    <arc-header></arc-header>

    <section class="hero">
        <h1 data-arc-t="home_heading">Cook with the season</h1>
        <p data-arc-t="home_lead">Short, honest recipes for whatever the market has this week.</p>
        <form class="signup" data-waitlist-form data-waitlist-id="newsletter">
            <input type="email" name="email" placeholder="Your email" data-arc-t-attr="placeholder:signup_email">
            <button type="submit" data-arc-t="signup_button">Get the weekly letter</button>
        </form>
    </section>

    <arc-content-partials content-type="blog" count="3" section-title="Latest from the blog"
        data-arc-t-attr="section-title:latest_posts"></arc-content-partials>

    <arc-footer></arc-footer>
    <script src="/site/main.js" defer></script>
</body>
</html>

.hero p { color: var(--muted); font-size: 1.25rem; }

/* Arc CMS adds the terms notice just before the button: give it its own line, under the form. */

The last rule in home.css puts the terms notice on its own line: Arc CMS inserts it just before the button, which in a one-line form squeezes it between the field and the button.

The script now starts either way, whether the page is still loading or already loaded. In npm run dev your scripts run after the page has loaded, so a script that waits for DOMContentLoaded would never start there:

// Fades cards in as they scroll into view. Runs whether the page is still
// loading (the published page) or already loaded (the preview in npm run dev).
(function () {
    function start() {
        if (!('IntersectionObserver' in window)) return;
        var seen = new IntersectionObserver(function (entries) {
            entries.forEach(function (entry) {
                if (entry.isIntersecting) { entry.target.style.opacity = 1; seen.unobserve(entry.target); }
            });
        });
        document.querySelectorAll('.card').forEach(function (card) {
            card.style.opacity = 0;
            card.style.transition = 'opacity .6s';
            seen.observe(card);
        });
    }
    if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', start);
    else start();
})();

Run npm run dev and open /: the header, hero, form and footer appear from your files. The cards stay empty until the blog has a published post.

4. The Blog content type

Do this after the template files exist in src/custom/site/templates/blog/ (steps 5 to 7), so the admin offers the folder. In the admin, open Content, Content types, Add Content Type:

SettingValue
Content Type Name (Plural)Blog
Singular NamePost
DescriptionEvery recipe and kitchen note, newest first. (The list page shows it as {{ contentTypeDescription }}.)
Generate public pagesOn
Content Type Slugblog, filled in from the name. It is the address (/blog) and the name the content is stored under, so do not change it once posts exist.
Content TemplateBlog, picked for you because the folder has the slug's name
Field 1Name Hero Image, type image. Its key is blog-hero-image.
Field 2Name Related Links, type labelvalue (rows of a label and a value). Its key is blog-related-links.
Structured dataBlog post

Title, body, summary, author, tags, dates and the reading time are built in, so the old page's date, author and "6 min read" need no fields. A template writes a custom field by its key ({{ blog-hero-image }}) or by the key without the type's slug ({{ hero-image }}); this example uses the short form. An image field also has four sizes: {{ hero-image_s }}, _m, _l and _xl. Every field type and what a template gets from it is in the field types reference.

5. The blog list

Copy the middle of docs/examples/blog/original/blog.html into src/custom/site/templates/blog/list.html: no doctype, <head> or <body>. Then keep one card and turn it into the pattern every post repeats:

OldNew
Navigation and footer<arc-header> and <arc-footer>, where they should appear
"The blog", the intro line{{ contentType }}, {{ contentTypeDescription }}: the type's name and description, translated with the type
Two hand-written cardsOne card inside data-arc-loop="items". The loop repeats its first child once per post, newest first (up to 100)
post.html, the title, date, "6 min read", the teaser{{ url }}, {{ title }}, {{ publishedOn }}, {{ readTime }}, {{ excerpt }} (the meta description, or the start of the body)
images/squash.jpg{{ hero-image_m }}, with data-arc-if="hero-image" so a post without one shows no broken image
 
<!-- The blog list page, /blog. A fragment: publishing wraps it in a page with
     the type's name as the title and its description. -->
<arc-header></arc-header>

<section class="posts">
    <h1>{{ contentType }}</h1>
    <p class="intro">{{ contentTypeDescription }}</p>
    <div class="post-grid" data-arc-loop="items">
        <article class="card">
            <img data-arc-if="hero-image" src="{{ hero-image_m }}" alt="">
            <div class="body">
                <h3><a href="{{ url }}">{{ title }}</a></h3>
                <p class="meta">{{ publishedOn }} · <span data-arc-t="min_read">{{ readTime }} min read</span></p>
                <p>{{ excerpt }}</p>
            </div>
        </article>
    </div>
</section>

<arc-footer></arc-footer>
<script src="/site/main.js" defer></script>

Publishing puts the list in a page whose title is the type's name and whose description is the type's description. The <script> moves to the end of the page.

6. The cards

src/custom/site/templates/blog/partials.html draws the cards for <arc-content-partials content-type="blog"> on the home page. It has the same items as the list, plus {{ sectionTitle }} (the element's section-title), {{ listUrl }} (the list page, in the page's language) and hasItems, which hides the whole block while there are no posts:

<!-- Cards for <arc-content-partials content-type="blog">: the home page's
     latest posts. A fragment: no <html>, <head> or <body>. -->
<section class="posts" data-arc-if="hasItems">
    <h2>{{ sectionTitle }}</h2>
    <div class="post-grid" data-arc-loop="items">
        <article class="card">
            <img data-arc-if="hero-image" src="{{ hero-image_m }}" alt="">
            <div class="body">
                <h3><a href="{{ url }}">{{ title }}</a></h3>
                <p class="meta">{{ publishedOn }}</p>
            </div>
        </article>
    </div>
    <p><a href="{{ listUrl }}" data-arc-t="all_posts">All posts</a></p>
</section>

7. One post

src/custom/site/templates/blog/detail.html is the middle of docs/examples/blog/original/post.html, with the post's values in place of the written ones:

OldNew
The cover image{{ hero-image_l }}, inside data-arc-if="hero-image"
Date, author, reading time{{ publishedOn }}, {{ authorName }}, {{ readTime }}
The article's paragraphs<div [innerHTML]="content"></div>. The body is HTML; {{ content }} would show its tags as text. The same goes for any rich text field.
The "Read next" listOne <li> inside data-arc-loop="related-links", with {{ label }} and {{ value }} from each row
blog.html{{ langPrefix }}/blog, so a Hindi post links back to the Hindi list
The post's own stylesA <style> block in the template; publishing moves it into the page's head
 
<!-- One blog post, /blog/{slug}. A fragment: publishing wraps it in a page
     with the post's SEO title, description and structured data. -->
<arc-header></arc-header>

<article class="post">
    <img class="cover" data-arc-if="hero-image" src="{{ hero-image_l }}" alt="{{ title }}">
    <h1>{{ title }}</h1>
    <p class="meta">
        {{ publishedOn }}
        <span data-arc-if="authorName">· <span data-arc-t="by_author">by {{ authorName }}</span></span>
        · <span data-arc-t="min_read">{{ readTime }} min read</span>
    </p>
    <!-- The body is HTML: [innerHTML], never {{ content }}, which would show the tags. -->
    <div class="content" [innerHTML]="content"></div>

    <aside class="related" data-arc-if="related-links">
        <strong data-arc-t="read_next">Read next</strong>
        <ul data-arc-loop="related-links">
            <li><a href="{{ value }}">{{ label }}</a></li>
        </ul>
    </aside>

    <p><a href="{{ langPrefix }}/blog" data-arc-t="back_to_blog">Back to the blog</a></p>
</article>

<arc-footer></arc-footer>

8. Try it in npm run dev

  1. Open Content, Blog, Add Post. Write the title and body, pick a hero image with Select image, and add two Related Links rows (a label, and the link as the value). The URL slug is made from the title.

  2. Press Save as draft, then open /blog/{{ your-slug }}?preview=true. You see the post drawn by your detail.html: the cover, title, date, author, reading time, body and links.

  3. The editor says Live site differs beside Publish: your new files are not on the live site yet, and publishing reads the live ones. Publishing now fails with "Template folder 'blog' is not on the live site. Deploy the website, then publish again." The post is still saved as published, so /blog and the home page's cards show it in npm run dev.

9. Put it live

  1. Deploy the website: npm run deploy and choose Website (see Deploy). It puts your files on the live site, keeps the pages already published, and then publishes every page again, your posts included.

  2. Open the live site: / shows the newest posts as cards, /blog the list, and each post its own page with its title and description in the page's head.

  3. From now on, publishing a post updates its page, the list, the home page's cards, the sitemap and the feeds. A change to your files reaches the live site with the next website deploy.

10. Add a second language

  1. Turn the language on under Settings, Languages (see Publish in more than one language).

  2. Put the translations of every data-arc-t key in src/custom/site/strings/hi.json. A translation may hold a value, such as {{ readTime }}, which is filled in afterwards. data-arc-t-attr="placeholder:signup_email" translates an attribute; the home page uses it for the field's placeholder and for the cards' section-title.

The Hindi text is only an example; have yours checked by a native speaker.

Common mistakes

You seeWhy, and what to do
"Template folder 'blog' is not on the live site"The website was not deployed after adding the folder. Deploy it, then publish again.
The post shows the default designThe type's Content Template is still Default, or your template file is a whole document (it has <html>, <head> or <body> tags). Keep templates fragments.
The body shows tags such as <p>It was written {{ content }}. Use [innerHTML]="content".
A list shows one post only, or the cards are emptyThe loop keeps only its first child as the pattern: wrap each card in one element. Cards also need hasItems true, that is, a published post.
An empty form appears under Signup FormsThe page's data-waitlist-id named a form that did not exist, so one was created. Fix the spelling, and delete the extra form.
An icon disappears from a translated buttondata-arc-t replaces the element's text, children included. Put icons outside the element that has data-arc-t.
A script works live but not in npm run devIt waits for DOMContentLoaded, which has already happened in the app. Start it as main.js does.
