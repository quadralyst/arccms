Build a website

This path takes you from an installed Arc CMS to a live content website that collects sign-ups. Follow the pages in order; each one says what to do in the admin area or the files, and links to the feature page for the detail.

What you will have at the end

  • Content types (articles, guides, case studies) that editors write and publish from the admin area, each published as a static page at /{type}/{item}.
  • Your own HTML templates for the list and detail pages, with your header and footer.
  • Static pages such as the privacy and cookie policies.
  • Structured data, a sitemap, robots.txt, llms.txt and RSS feeds, written on every publish.
  • A search box in the header and a /search results page.
  • A signup form on the home page, with a verification code, a welcome email, referrals and a leaderboard. Every sign-up becomes a contact you can email.

Before you start

You need an installed Arc CMS with its first admin. If you have not done that yet, follow Install, Configure a project and Create the first admin. The first-run wizard creates an Articles content type and a default signup form, so you do not start from nothing.

Have these ready:

A list of your pages and their fieldsYou turn it into content types in the next two pages.

The steps

  1. Plan your content: decide what is a content type, a static page or a form, and what each URL looks like.

  2. Define content types: create them in the admin area with their fields.

  3. Design templates: give each content type its list and detail layout.

  4. Write static pages: the legal pages and anything else that rarely changes.

  5. Manage media: set image sizes and upload images.

  6. Add authors and tags: bylines and topics.

  7. Get found by search engines and AI: fill in your site identity and write pages that get quoted.

  8. Publish in more than one language: only if you need it.

  9. Add search: choose what visitors can search.

  10. Collect sign-ups: set up the form, its emails and where sign-ups land.

  11. Choose your website's features: switch off what a website does not use.

  12. Launch checklist: check everything before you point your domain at it.

Recommended features

A content website with lead generation uses content, templates, media, authors and tags, SEO, search, signup forms, audience and email. Keep them all on. Switch off payments and SMS unless you sell or use phone sign-in; Choose your website's features shows how. The full list is in All features.

How you work

Most of the work happens in the admin area at /admin. The rest is editing files that ship with Arc CMS:

File or folderWhat you change there
public/templates/The list and detail layouts of your content types
public/pages/The privacy and cookie policies
public/_partials/_header.html, public/_partials/_footer.htmlThe site header (menu, search box, language switcher) and footer
public/index.htmlThe home page, with its signup form
index.htmlThe home page's browser title
src/shared/constants/legal-notice.tsThe terms and privacy links in the notice on signup forms
src/custom/features.tsThe features you switch off

Except src/custom/features.ts, these are core files: a website edits them in place, npm run check:core lists them as core changes, and an upgrade can conflict where Arc CMS changed the same file (see Upgrade Arc CMS).

The home page and the header and footer are compiled into the app as Angular templates, so a literal {, } or @ in their text stops the build. Write &#123;, &#125; and &#64; instead.

Run the site locally with npm run dev while you build; it reads and writes your real Firebase project (see Run it locally). Publishing an item puts its page on the live site straight away. Changes to files reach the live site when you deploy the website (see Deploy).
