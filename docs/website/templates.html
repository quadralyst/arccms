Design templates

A template is your own HTML with a few Arc CMS attributes that say where the content goes. Copy a folder, change the markup, register it, and pick it on the content type. The full syntax is in Templates.

Start from a shipped folder

Arc CMS ships three folders in public/templates/:

FolderFilesUse it as
public/templates/default/list.html, detail.htmlThe layout of any content type without a folder of its own. It already shows sources, related items, the author box and the common repeating fields.
public/templates/articles/list.html, detail.html, partials.htmlA blog layout
public/templates/manuals/list.html, detail.html, partials.htmlA documentation layout

list.html renders /{type}, detail.html renders /{type}/{item}, and the optional partials.html renders cards of a type inside another page.

Make your own

  1. Copy the folder closest to your design, for example public/templates/articles/ to public/templates/case-studies/.

  2. Add the folder name to the folders list in public/templates/templates.json. Only listed folders appear in the admin; default is always offered.

  3. Replace the markup and styles with your design. Keep each file an HTML fragment: no doctype and no <html>, <head> or <body>. Styles can sit in a <style> block in the file.

  4. Keep <arc-header></arc-header> and <arc-footer></arc-footer> in the list and detail files; they become the site header and footer from public/_partials/. Leave them out of partials.html.

  5. In the admin, open Content, Content types, edit the type, and choose the folder under Content Template.

A template that is a whole HTML document (with a doctype, <html>, <head> or <body>) is not used: the app shows the default layout instead, and a published page gets a bare built-in layout. So is a folder that does not exist on the site. If your page does not look like your template, check both.

Put the content in

Four attributes and one placeholder do the work:

WriteTo
{{ title }}Insert a value into text or an attribute, such as href="{{ url }}"
data-arc-bind="title"Replace the element's content with a value; on an <img> it sets the source, on an <a> the link
data-arc-loop="items"Repeat the first child once per item (on a list page), per tag (tags) or per row of a repeating field; data-limit="6" caps it
data-arc-if="coverImage"Remove the element when the value is empty
data-arc-t="read_more"Translate fixed text into the page's language (see Publish in more than one language)

The values you can use are listed in the admin: open Content types, press View on a type, and read its Template Reference. It shows the built-in values (title, url, coverImage, summary, publishedOn, readTime and more), the detail-only ones (share links, previous and next), and the type's own custom fields. A custom field is written by its key without the type slug, so one template can serve several types. Every image also has sized versions, such as {{ coverImage_m }} (see Manage media).

Placeholder text you put inside an element stays in the template file, but not on the page: a loop keeps only its first child, and a loop with no rows is emptied. Write one example row, and hide an empty container with CSS such as :empty { display: none; }.

Preview

Run npm run dev, open an item in the editor and press Preview. The page opens at /{type}/{item}?preview=true, rendered with your local template files, so you can edit the HTML and reload. The list page is at /{type}. Test with long titles, a missing cover image and empty fields.

Put it live

Publishing reads the template from the live site, not from your computer. Deploy the website once your templates are ready (see Deploy): the website deploy also republishes every page with the new templates. The same applies after you change the header or footer in public/_partials/.

Publishing an item after editing its template locally, but before deploying the website, produces a page with the old template. Deploy the website first.

Cards on the home page

The home page, public/index.html, can show cards of any type with <arc-content-partials [contentType]="'articles'"></arc-content-partials>, laid out by that type's partials.html (a type on the default folder gets built-in cards). This element works on the home page only; content pages and static pages do not render it.
