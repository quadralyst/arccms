Design templates

A template is your own HTML with a few Arc CMS attributes that say where the content goes. Copy a folder into your site folder, change the markup, and pick it on the content type. The full syntax is in Templates.

Start from a shipped folder

Each content type with public pages has three templates:

FileRenders
list.htmlThe list of the type, /{type}
detail.htmlOne item, /{type}/{item}
partials.htmlCards of the type inside another page, such as the latest articles on the home page

Arc CMS ships three folders of them in public/_site/templates/:

FolderUse it as
public/_site/templates/default/The layout of any content type without a folder of its own, so every type renders even if you write no template. It already shows sources, related items, the author box and the common repeating fields.
public/_site/templates/articles/A blog layout
public/_site/templates/manuals/A documentation layout

These are core files: read and copy them, never edit them.

Make your own

  1. Copy the folder closest to your design into your site folder under a new name, for example public/_site/templates/articles/ to src/custom/site/templates/case-studies/. Keep only the files you change: a file your folder lacks is taken from default, so a folder with just detail.html is complete.

  2. Replace the markup and styles with your design. Keep each file an HTML fragment: no doctype and no <html>, <head> or <body>. Styles can sit in a <style> block in the file, or in src/custom/site/site.css for styles every page shares.

  3. Keep <arc-header></arc-header> and <arc-footer></arc-footer> in the list and detail files; they become the site header and footer. Leave them out of partials.html.

  4. In the admin, open Content, Content types, edit the type, and choose the folder under Content Template. The list shows every folder your site has, with nothing to register. A new type whose slug matches a folder name, such as case-studies, gets that folder picked for it.

To change one of Arc CMS's folders instead, put a file at the same path in your site folder: src/custom/site/templates/default/detail.html replaces the default detail layout and leaves its list and cards as Arc CMS ships them.

The header and footer work the same way: src/custom/site/header.html and src/custom/site/footer.html replace Arc CMS's (public/_site/header.html, public/_site/footer.html). They are plain HTML fragments; <arc-search> and <arc-language-switcher> in the header become the search box and the language links.

A template that is a whole HTML document (with a doctype, <html>, <head> or <body>) is not used: the app shows the default template instead, and a published page gets a bare built-in layout. If your page does not look like your template, check that first. A file in your site folder that is not a template, page or other site file (say templates/case-studies/card.html) is not served; npm run dev lists it in a warning.

Put the content in

Four attributes and one placeholder do the work:

WriteTo
{{ title }}Insert a value into text or an attribute, such as href="{{ url }}"
data-arc-bind="title"Replace the element's content with a value; on an <img> it sets the source, on an <a> the link
data-arc-loop="items"Repeat the first child once per item (on a list page), per tag (tags) or per row of a repeating field; data-limit="6" caps it
data-arc-if="coverImage"Remove the element when the value is empty
data-arc-t="read_more"Translate fixed text into the page's language (see Publish in more than one language)

The values you can use are listed in the admin: open Content types, press View on a type, and read its Template Reference. It shows the built-in values (title, url, coverImage, summary, publishedOn, readTime and more), the detail-only ones (share links, previous and next), and the type's own custom fields. A custom field is written by its key without the type slug, so one template can serve several types. Every image also has sized versions, such as {{ coverImage_m }} (see Manage media).

Placeholder text you put inside an element stays in the template file, but not on the page: a loop keeps only its first child, and a loop with no rows is emptied. Write one example row, and hide an empty container with CSS such as :empty { display: none; }.

Preview

Run npm run dev, open an item in the editor and press Preview. The page opens at /{type}/{item}?preview=true, rendered with your local template files, so you can edit the HTML and reload. The list page is at /{type}. Test with long titles, a missing cover image and empty fields.

Put it live

Publishing reads the templates, header and footer from the live site, not from your computer. Deploy the website once your templates are ready (see Deploy): the website deploy also republishes every page with the new templates.

Publishing an item after editing its template locally, but before deploying the website, produces a page with the old template. Deploy the website first.

Cards on the home page

The home page, public/index.html, can show cards of any type with <arc-content-partials [contentType]="'articles'"></arc-content-partials>, laid out by that type's partials.html (its folder's, else the default's). This element works on the home page only; content pages and static pages do not render it.
