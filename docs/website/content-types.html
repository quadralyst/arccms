Define content types

Turn each content type from your plan into a type in the admin area, then write and publish one item to see the whole flow work. The full reference is Content.

Create a content type

  1. In the admin menu open Content, then Content types, and press Add Content Type. (Articles is already there from the first-run wizard; edit it rather than adding a second one.)

  2. Fill in Content Type Name (Plural) and Singular Name, for example Case Studies and Case Study. The plural heads the list page and the admin menu; the singular labels buttons such as Add Case Study.

  3. Add a Description (shown under the list page heading) and pick an Icon (Font Awesome) for the admin menu.

  4. Leave Generate public pages on, unless only your app's own pages read the items. With it off, the type shows nowhere on the published site, not even as cards in a card block, and the next two settings are hidden.

  5. Check the Content Type Slug. It is filled in from the name and becomes the URL: case-studies gives /case-studies. Lowercase letters, numbers and hyphens only.

  6. Check the Content Template. A template folder with the same name as the slug is picked for you; otherwise it is Default Template. You can switch to your own folder after Design templates.

  7. Under Custom fields, press Add Field for each extra field in your plan: give it a Name, a Type and, if it must be filled in before publishing, tick Required.

  8. Press Save Content Type. The type appears in the admin menu under Content.

Structured data (see Get found by search engines and AI) is at the bottom of the form when you add a type and when you edit it: choose a type such as Product or Event and map its properties to the custom fields you have added. When you edit a saved type, the form also has Searchable custom fields (see Add search).

Settle the slug before you write items. Items are stored under the slug (arc_{slug}), so changing it later hides every existing item of the type, in the admin area and on the site.

What each type stores and how a template shows it, with an example per type, is in the field types reference.

Each field gets a key from its name, shown under the name as you type. Templates use that key, and it is fixed once the type is saved: renaming the field later changes only its label, so name fields carefully. Do not add fields for what every item already has (title, URL slug, cover image, body, summary, dates, tags, author, read time).

A few rules worth knowing before you add fields:

  • Required is checked when you press Publish. Drafts and previews save with the field empty.
  • You can change a field's Type after saving, but values already written are not converted, so check the items that have one.
  • Deleting a field takes it out of the editor, but the values stay stored on each item, and a template that names the key still shows them.
  • In a second language, only text, rich text and the words in repeating fields (headlines, captions, labels, addresses) are translated. Every other field is shared by all languages.

The default template already shows three repeating fields, with no template work, when they are named exactly Gallery (a gallery field), Details (a labelvalue field) or Locations (a maplocation field). Any other repeating field needs a template that loops over it.

Write and publish an item

  1. Open the type in the admin menu under Content, and press Add followed by the singular name.

  2. Write the title and the body. The editor has headings, lists, tables, images, links and code, plus ready-made blocks (FAQ, Key takeaways, How-to steps, Definition) from the toolbar's grid icon.

  3. In the Basic tab, fill in the Summary, check the URL Slug, and pick a Cover Image, Tags, an Author and the custom fields. The summary also fills the SEO meta description until you edit that yourself. List cards show the meta description, or the first 25 words of the body when there is none.

  4. Press Preview. It saves a draft and opens the page in a new tab, rendered with the type's template.

  5. Press Publish. The page is written to the live site, and the list page, sitemap and feeds are updated.

Save as draft keeps work unpublished; the editor also saves as you type. The History tab keeps earlier versions you can restore. From the content list you can Unpublish an item, choose the Columns shown, and Bulk Import items from a CSV or Excel file.
